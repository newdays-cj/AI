# 虚拟机热迁移与 Dirty Tracking 技术说明

## 1. 概述

虚拟机热迁移（Live Migration）是指将正在运行的虚拟机从源主机转移到目标主机，并尽量缩短业务中断时间。

迁移需要转移的主要状态包括：

| 状态 | 主要内容 |
|---|---|
| 内存状态 | Guest 内存中的操作系统、应用和数据 |
| vCPU 状态 | 寄存器、指令指针及相关执行状态 |
| 设备状态 | 虚拟设备配置、队列、中断及必要的在途 I/O 状态 |
| 存储状态 | 非共享存储场景下需要同步的磁盘数据 |

热迁移的核心难点在于：**内存复制期间，虚拟机仍在运行，并持续修改内存。**

Dirty Tracking（脏页跟踪）用于识别这些修改，使迁移程序能够重新同步已经过期的页面。它是预拷贝迁移实现增量传输、控制停机时间和保证最终状态一致性的重要机制。

## 2. 热迁移的基本流程

常见的热迁移策略包括预拷贝（Pre-copy）、后拷贝（Post-copy）及两者结合的混合模式。以下以预拷贝为主线说明。

```text
准备目标虚拟机
       |
开启脏页跟踪
       |
全量复制内存 -------------------+
       |                       |
获取本轮脏页                   | 源虚拟机持续运行
       |                       | 并修改内存
迭代复制脏页 -------------------+
       |
判断是否满足切换条件
       |
暂停源虚拟机，协调设备停止写入
       |
同步最终脏页、vCPU 和设备状态
       |
目标虚拟机恢复运行
       |
确认迁移成功，释放源端资源
```

### 2.1 准备目标环境

目标主机创建待恢复的虚拟机实例，准备内存、vCPU 和虚拟设备，并建立迁移通道。

主要准备条件包括：

- 两端 CPU 特性和虚拟机配置兼容。
- 虚拟设备支持相应的状态保存与恢复。
- 目标端能够访问虚拟机磁盘，或具备独立的磁盘迁移机制。
- 网络连接及转发状态能够完成切换。

如果使用共享存储，通常无需复制磁盘内容；如果使用本地存储，则需要另外同步磁盘数据。内存脏页跟踪不能替代磁盘同步。

### 2.2 全量复制内存

迁移程序开启脏页跟踪后，开始复制全部需要迁移的内存。此时源虚拟机继续运行。

由于页面可能在复制后被再次修改，目标端的部分页面会很快过期。例如：

```text
t0：源端页面 P 的内容为 A
t1：将 P=A 复制到目标端
t2：虚拟机将源端 P 修改为 B
```

Dirty Tracking 将页面 P 标记为脏页，使它在后续轮次中重新发送。

第一轮内存复制本身并不是一个一致性快照，因为不同页面是在不同时间读取的。系统需要通过后续增量复制和最终暂停同步，获得可恢复的完整状态。

### 2.3 迭代复制脏页

全量复制结束后，迁移程序获取脏页集合，只重新发送被修改的页面。复制期间产生的新写入继续被跟踪，供后续轮次处理。

```text
第 1 轮：发送全部内存，记录期间产生的脏页
第 2 轮：发送第 1 轮脏页，继续记录新的脏页
第 3 轮：发送第 2 轮脏页，继续记录新的脏页
……
```

如果新增脏页较少，需要传输的数据通常逐轮减少；如果虚拟机持续修改大量页面，迭代可能难以收敛。

### 2.4 判断切换条件

迁移程序根据以下信息决定是否进入最终切换：

- 剩余脏页数量。
- 有效传输带宽。
- 允许的停机时间。
- 已用迁移时间及策略限制。

预计停机时间可粗略表示为：

```text
T_downtime ≈ M_remaining / B_effective + T_state
```

其中：

- `M_remaining`：最终需要发送的剩余内存数据量。
- `B_effective`：有效内存传输带宽。
- `T_state`：vCPU、设备状态同步及目标端恢复等耗时。

### 2.5 暂停与最终同步

进入最终切换阶段后，源端暂停 vCPU，并协调设备及相关后端停止或冻结会继续修改迁移状态的操作。

随后完成：

1. 获取并传输最后一批脏页。
2. 同步 vCPU 寄存器及相关执行状态。
3. 同步虚拟设备、中断控制器、计时器等状态。
4. 处理必要的在途 I/O。
5. 确保目标端具备一致的恢复状态。

这一阶段建立了最终的一致性边界：源端不再产生未被迁移捕获的状态变化，目标端才能从同一执行位置继续运行。

### 2.6 恢复与清理

目标端恢复虚拟机，并完成网络、存储等访问路径的切换。确认迁移成功后，释放源端资源。

业务中断时间主要由最终暂停、目标端恢复及网络切换决定，而非整个内存复制过程。

## 3. Dirty Tracking 的作用

### 3.1 识别需要重新发送的页面

Dirty Tracking 通常以 Guest 物理页为跟踪对象，记录页面在某个跟踪周期内是否发生过写入。

例如，使用脏页位图表示：

| Guest 物理页 | 脏标记 | 含义 |
|---|---:|---|
| P0 | 0 | 本周期未记录到写入 |
| P1 | 1 | 本周期发生过写入 |
| P2 | 0 | 本周期未记录到写入 |
| P3 | 1 | 本周期发生过写入 |

后续迁移轮次需要考虑重新发送 P1 和 P3。

这种机制通常只记录“页面是否变脏”，不记录每一次写入，也不保存页面内部的修改历史。同一页面在一轮内被反复修改，通常只需在该轮重传集合中出现一次。

### 3.2 降低重复传输量

没有脏页信息时，迁移程序难以准确识别目标端哪些页面已经过期。

Dirty Tracking 提供增量传输依据，使后续轮次只发送可能发生变化的页面，减少网络传输和内存读取开销。

### 3.3 为迁移策略提供依据

脏页数量及其变化速度可以反映内存同步的进展，用于：

- 估算剩余传输量和预计停机时间。
- 判断迭代是否收敛。
- 决定继续预拷贝还是进入最终切换。
- 触发限速、工作负载节流或迁移策略切换。

### 3.4 支持最终状态一致性

Dirty Tracking 负责指出哪些页面可能需要重传，但不能独立保证整个虚拟机状态一致。

完整的一致性还依赖：

- 脏页日志的并发处理正确。
- CPU 和设备等内存写入来源均被覆盖。
- 最终切换期间写入得到协调。
- 内存、vCPU 和设备状态按照迁移协议完成同步。

## 4. Dirty Tracking 的常见实现

### 4.1 写保护与写故障

Hypervisor 对相关二级地址映射设置写保护。Guest 首次写入时触发陷入，Hypervisor 记录脏页，并根据策略恢复写权限。

后续跟踪周期需要重新建立相应的跟踪条件。

这种方式会产生写故障处理、页表更新及必要的 TLB 失效开销。

### 4.2 硬件脏位

在支持的架构上，可以利用 EPT/NPT 等二级页表的 Dirty Bit 识别页面写入，减少部分软件陷入。

迁移系统仍需要正确处理脏位的读取、清除及相关地址转换缓存同步。

### 4.3 日志机制与用户态接口

硬件或 Hypervisor 可以通过日志结构记录脏页，减少扫描或信息交换开销。例如：

- Intel PML 可辅助记录变脏的 Guest 物理地址。
- KVM 提供 dirty bitmap、dirty ring 等机制向用户态暴露脏页信息。

硬件记录方式与用户态日志接口属于不同层次，具体组合取决于 CPU、内核和虚拟化软件实现。

## 5. 正确性与性能约束

### 5.1 脏标记清除不能遗漏并发写入

复制页面、获取脏页信息和清除脏标记之间存在竞争。例如：

```text
迁移线程读取页面
        |
Guest 修改页面
        |
迁移线程错误地清除脏标记
        |
该修改未进入后续重传集合
```

如果发生这种情况，目标端可能保留旧数据。

正确实现必须保证：

> 对复制过程中发生的写入，要么其结果已包含在本次发送的数据中，要么对应页面会在后续轮次重新发送。

保守地多报脏页会增加传输量；漏报需要同步的页面则会破坏迁移正确性。

### 5.2 必须覆盖设备写入

Guest 内存的写入来源包括：

- vCPU 执行的写操作。
- 用户态设备模拟程序。
- 内核设备后端，例如 vhost。
- 直通设备的 DMA。

CPU 页表脏位通常不能自动覆盖所有 DMA 写入。迁移系统需要结合设备后端标记、设备或 IOMMU 的跟踪能力，以及最终阶段的设备停止机制。

因此，直通设备是否支持热迁移，不仅取决于内存能否复制，也取决于设备状态和 DMA 写入能否被正确迁移与跟踪。

### 5.3 跟踪粒度影响传输放大

脏页跟踪通常按页记录，而非按应用实际修改的字节数记录。

例如，在许多不同的 4 KiB 页面上各修改 1 字节，可能导致这些页面全部需要重新发送。因此，应用写入带宽较低，并不一定意味着迁移产生的脏页数据量较小。

### 5.4 脏页产生速率影响收敛

设：

- `M_n`：第 n 轮待发送数据量。
- `B`：有效传输带宽。
- `D`：按跟踪粒度折算的有效脏页产生速率。

在简化模型下：

```text
M_(n+1) ≈ D × (M_n / B)
```

当 `D < B` 时，通常有利于逐轮减少剩余数据量；当 `D` 接近或超过 `B` 时，可能长期重复传输大量页面。

实际收敛还受到页面重复写入、工作集大小、传输编码及处理开销等因素影响。

对于难以收敛的负载，可以增加有效带宽、降低写入速率、限制 vCPU 执行速度，或在支持的情况下切换迁移模式。

## 6. 与 Post-copy 的关系

Post-copy 较早暂停源端并将执行切换到目标端，剩余内存随后通过后台传输和按需取页补齐。

| 对比项 | Pre-copy | Post-copy |
|---|---|---|
| 主要复制期间的执行位置 | 源端 | 目标端 |
| 内存同步方式 | 全量复制后反复重传脏页 | 后台复制与按需取页 |
| 主要难点 | 高写入负载下可能难以收敛 | 缺页延迟及对源端、链路的持续依赖 |
| Dirty Tracking 的角色 | 驱动增量复制与收敛判断 | 纯后拷贝阶段通常不以源端脏页重传为核心 |

实际系统可以先执行 Pre-copy，再切换到 Post-copy。这种混合模式的预拷贝阶段仍需要 Dirty Tracking；进入后拷贝后，页面位置管理和缺页处理成为主要机制。

如果源端或迁移链路在后拷贝尚未完成时故障，目标端可能因无法获取剩余页面而无法继续运行。
