# 07.1-自审清单（v3 — pre_eject 回调机制）

## 审查范围

本次 diff（working tree，3 文件 +24/-9 行）：
- `include/acpi/acpi_bus.h`：`struct acpi_hotplug_profile` 追加 `void (*pre_eject)(struct acpi_device *adev)` 字段
- `drivers/acpi/scan.c`：`acpi_scan_hot_remove` 中 `acpi_bus_trim` 前保存 handler、trim 后调用 `pre_eject`
- `drivers/soc/hisilicon/hisi_hbmdev.c`：函数重命名 + 新增 `hbmdev_pre_eject` 包装器 + `memdev_power_off` 注册回调 + `state_store` 移除 `on_each_cpu`

## 1. 功能完整性

| 检查项 | 结果 | 说明 |
|---|---|---|

| 仅 OFFLINE 触发，ONLINE 不触发 | ✅ | `pre_eject` 回调仅在 `memdev_power_off`（STATE_OFFLINE 分支）中注册，STATE_ONLINE 路径不触及 |
| 广播到所有 CPU | ✅ | `hbmdev_pre_eject` → `on_each_cpu(smc_flush_cache, NULL, true)` 同步广播 |

| 失败仅 warn 不阻断 | ✅ | `pr_warn` 后无 return/break，`on_each_cpu` 返回后继续 `_EJ0` 流程 |

## 3. 并发安全

| 检查项 | 结果 | 说明 |
|---|---|---|
| `pre_eject` 调用上下文 | ✅ | `acpi_scan_hot_remove` 在 kworker 中执行，进程上下文，持有 `acpi_scan_lock` |
| `on_each_cpu(wait=true)` 语义 | ✅ | 同步等待所有 CPU 完成回调后才返回；回调在 IPI 上下文运行（IRQ 禁止） |
| IPI 上下文安全性 | ✅ | `arm_smccc_smc` = 同步 `smc #0` trap（不睡眠/不调度）；`pr_warn` = `printk` 变体，安全于任意上下文 |
| 回调注册时序 | ✅ | `pre_eject` 在 `memdev_power_off` 中 `acpi_hotplug_schedule` 之前设置，kworker 执行时回调已就位 |
| `dev_lock` 与异步 kworker | ✅ | `memdev_power_off` 设置回调后 `acpi_hotplug_schedule` 异步调度；`state_store` 中 `flush_hotplug_workqueue` 等待所有 kworker 完成；`dev_lock` 在 `flush_hotplug_workqueue` 期间持有 |
| 多设备并发弹出 | ✅ | `memdev_power_off` 为每个子设备独立调度 `acpi_hotplug_schedule`；每个设备独立走 trim→pre_eject→_EJ0；`acpi_scan_lock` 串行化 `acpi_scan_hot_remove` |
| 不引入新锁依赖 | ✅ | 无新增锁获取；`on_each_cpu` 内部使用 `smp_call_function` 机制，不与 `dev_lock` / `acpi_scan_lock` 产生依赖 |

## 4. 边界情况与风险

| 场景 | 分析 | 结论 |
|---|---|---|
| SMC 返回 0（成功） | 不打印 warn，`on_each_cpu` 正常完成，继续 `_EJ0` | ✅ 正确 |
| SMC 返回负值（错误） | 每个 CPU 独立打印 `pr_warn`，`on_each_cpu` 仍正常完成，继续 `_EJ0` | ✅ 符合用户决策 |
| handler 为 NULL（非 HBM 设备） | `if (handler && ...)` 跳过，行为与未修改前一致 | ✅ 向后兼容 |
| `pre_eject` 为 NULL（未注册） | `if (... && handler->hotplug.pre_eject)` 跳过，行为与未修改前一致 | ✅ 向后兼容 |
| 多个 PNP0C80 子设备 | 每个设备独立注册 `pre_eject`，独立触发 SMC 广播 | ✅ 正确——每个设备内存独立移除 |
| `acpi_bus_trim` 失败 | trim 无返回值（void），`.detach` 失败不阻断；pre_eject 仍会调用 | ⚠️ 可接受——若 detach 部分失败，缓存刷新仍有意义 |
| STATE_ONLINE 路径 | `memdev_power_on` 不注册 `pre_eject` | ✅ 无影响 |
| 非 HIP11 平台 | `hbmdev_init` 返回 0，`pre_eject` 不注册 | ✅ 无影响 |

### 遗留项（非自审范围，需外部确认）
1. **FID `0x83009000` 需固件团队最终确认** — 当前基于固件团队反馈
2. **SMC conduit（SMC vs HVC）需固件确认** — 当前用 SMC，与现有 HiSilicon owner=3 SMC 一致
3. **`on_each_cpu` 广播范围的必要性需固件团队确认** — 当前理解为"每个 CPU 需执行 EL3 缓存刷新"
4. **QEMU 无法测试 SMC trap** — 需在 ⑨ 测试文档注明例外理由
5. **`struct acpi_hotplug_profile` 结构体变更需 kABI 复核** — 末尾追加字段理论安全，但需正式 kABI 检查确认
