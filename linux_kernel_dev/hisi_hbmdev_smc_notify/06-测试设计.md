# 06-测试设计（v3 — pre_eject 回调机制）

> **v3 修订说明**：v2 测试设计基于 `state_store` 中 `on_each_cpu` 调用。v3 将 SMC 调用移至 ACPI 核心的 `pre_eject` 回调，调用链变为 `acpi_scan_hot_remove` → `acpi_bus_trim`（remove_memory）→ `pre_eject`（SMC）→ `_EJ0`。测试用例相应更新，新增对 ACPI 核心改动的验证。

## 1. 测试策略概述

本特性（HBM 内存设备 `remove_memory` 后、`_EJ0` 前 SMC 缓存刷新）在 QEMU 环境中存在**根本性不可测约束**，测试策略采用"可测部分充分覆盖 + 不可测部分文档化例外"模式。

### 不可测根因分析

| 约束 | 根因 | 影响 |
|---|---|---|
| **平台门控** | `hbmdev_init()` 调 `acpi_match_platform_list(hbm_plat_info)`，仅 HIP11 平台返回 ≥0；QEMU virt 机器的 ACPI OEM 字段不匹配 | 模块在 QEMU 中 `module_init` 直接返回 0，`pre_eject` 回调不注册 |
| **SMC EL3 trap** | `arm_smccc_smc` 执行 `smc #0` 同步陷入 EL3；QEMU 不模拟 HiSilicon vendor SMC handler，FID `0x83009000` 返回 `SMC_UNK`(-1) | 即便绕过平台门控，SMC 必然失败 |
| **ACPI 设备树依赖** | `memdev_power_off` 遍历 `adev->children` 寻找 `PNP0C80` 设备；QEMU virt 不模拟 HIP11 HBM 内存设备的 ACPI 拓扑 | 无真实 HBM 内存设备可弹出，`pre_eject` 回调不可达 |
| **inline asm 不可 mock** | `arm_smccc_smc` 展开为 `smc #0` 指令，无函数指针/弱符号可覆盖 | KUnit 无法注入 mock SMC handler |

### 可测范围

| 测试类型 | 可行性 | 方式 |
|---|---|---|
| 编译验证 | ✅ 可测 | 交叉编译 3 个修改文件 + 完整 Image |
| 静态检查 | ✅ 可测 | `checkpatch.pl --strict` 对 patch |
| 反汇编验证 | ✅ 可测 | objdump 确认 `scan.o` 中 `acpi_bus_trim` → `blr pre_eject` → `acpi_evaluate_lck` → `acpi_evaluate_ej0` 调用链；`hisi_hbmdev.o` 中 `hbmdev_pre_eject` → `on_each_cpu_cond_mask` + `__arm_smccc_smc` |
| KUnit 单元测试 | ⚠️ 受限 | 仅能测编译期类型检查；运行时逻辑因 inline asm 不可 mock 而无法覆盖 SMC 调用本身 |
| QEMU 功能验证 | ❌ 不可测 | 平台门控 + ACPI 拓扑缺失 + SMC EL3 trap 三重阻断 |
| gcov 覆盖率 | ❌ 不可测 | 模块在 QEMU 不加载，无运行时执行路径 |

## 4. 例外理由详述

### 4.1 平台门控（影响 TC-05/06/07/09）

`hbmdev_init()` 第一行 `acpi_match_platform_list(hbm_plat_info) < 0` → return 0。QEMU virt 的 ACPI OEM 字段不匹配 "HISI  "/"HIP11  "。模块不加载，`memdev_power_off` 不执行，`pre_eject` 回调不注册，`state_store` 不可达。

**无法绕过**：修改 `hbm_plat_info` 等于修改产品代码以适配测试。

### 4.2 SMC EL3 trap（影响 TC-05/09）

`arm_smccc_smc` 执行 `smc #0` 陷入 EL3。QEMU 不模拟 HiSilicon vendor SMC handler，FID `0x83009000` 返回 `SMC_UNK`(-1)。即便绕过平台门控，SMC 必然失败。

### 4.3 inline asm + on_each_cpu 不可 mock

`__arm_smccc_smc` 是汇编函数，无弱符号/函数指针可覆盖。`on_each_cpu` 通过 IPI 广播，KUnit 无法模拟多 CPU IPI 行为。mock 需重构产品代码，超出特性范围。
