# 05-实现方案（v3 — pre_eject 回调机制）

> **v3 修订说明**：v2 设计（`state_store` 中 `flush_hotplug_workqueue` 之后 `on_each_cpu` 广播）已废弃。v3 满足固件团队要求：SMC 必须在 `remove_memory` 完成之后、`_EJ0` 设备下电之前调用。为此在 ACPI 热插拔核心引入 `pre_eject` 回调，vendor 驱动注册回调实现 SMC 广播。

## 1. 设计概述

在 `struct acpi_hotplug_profile` 中新增 `pre_eject` 回调，由 `acpi_scan_hot_remove()` 在 `acpi_bus_trim()`（含 `remove_memory`）完成之后、`acpi_evaluate_lck()` / `acpi_evaluate_ej0()`（设备下电）之前调用。HiSilicon `hisi_hbmdev` 驱动在 `memdev_power_off()` 中为每个 PNP0C80 子设备注册 `pre_eject` 回调，回调内通过 `on_each_cpu()` 广播 vendor SMC，触发各 CPU 的 EL3 级缓存刷新。

### 调用链

```
state_store(STATE_OFFLINE)
  → memdev_power_off()
      → for each PNP0C80 child:
          child->handler->hotplug.pre_eject = hbmdev_pre_eject   ← 注册回调
          acpi_hotplug_schedule(child, EJECT)                     ← 异步调度
  → flush_hotplug_workqueue()                                    ← 等待异步工作完成

[异步 kworker]
acpi_hotplug_schedule
  → acpi_scan_hot_remove(device)
      → acpi_bus_trim(device)                                     ← .detach → remove_memory
      → handler->hotplug.pre_eject(device)                        ← SMC 缓存刷新（v3 新增）
      → acpi_evaluate_lck(handle, 0)                             ← _LCK(0)
      → acpi_evaluate_ej0(handle)                                ← _EJ0 设备下电
```

## 2. 关键设计决策

| 项 | 值 | 理由 |
|---|---|---|
| FID | `ARM_SMCCC_CALL_VAL(ARM_SMCCC_FAST_CALL, ARM_SMCCC_SMC_32, ARM_SMCCC_OWNER_OEM, 0x9000)` = `0x83009000` | 用 `ARM_SMCCC_CALL_VAL` 宏符号化定义；owner=OEM 与仓库现有 HiSilicon SMC (TRNG/STL) 一致 |
| 回调机制 | `struct acpi_hotplug_profile` 新增 `pre_eject` 字段 | ACPI 核心最小侵入：2 行核心代码（声明 + 调用），NULL 默认值保证向后兼容 |
| 回调签名 | `void (*pre_eject)(struct acpi_device *adev)` | 与现有 `notify_online` 签名一致；传递 `adev` 供回调获知目标设备 |
| 回调注册位置 | `memdev_power_off()` 中 `acpi_hotplug_schedule` 之前 | 在调度弹出前设置回调，确保 kworker 执行时回调已就位 |
| 回调调用位置 | `acpi_scan_hot_remove()` 中 `acpi_bus_trim` 之后、`acpi_evaluate_lck` 之前 | 精确满足"remove_memory 之后、_EJ0 之前"要求 |
| handler 指针保存 | `handler = device->handler` 在 `acpi_bus_trim` 之前 | **关键**：`acpi_bus_trim()` 在 line 2136 将 `adev->handler` 置 NULL，若不提前保存则回调无法获取 handler |
| 广播机制 | `on_each_cpu(smc_flush_cache, NULL, true)` | 固件要求每个 CPU 都执行 EL3 缓存刷新；`wait=true` 同步等待 |
| SMC 粒度 | 每个 PNP0C80 设备一次 | `memdev_power_off` 为每个子设备单独调度 `acpi_hotplug_schedule`，每个设备独立走 trim→pre_eject→_EJ0 流程 |
| 失败策略 | `pr_warn` + 继续 | 不阻断 offline 流程；每个 CPU 独立报告失败 |

## 3. v2 → v3 关键差异

| 维度 | v2（已废弃） | v3（当前） |
|---|---|---|
| 调用位置 | `state_store` 中 `flush_hotplug_workqueue` 之后 | `acpi_scan_hot_remove` 中 `acpi_bus_trim` 之后、`_EJ0` 之前 |
| 时机 | 所有设备弹出后（全局一次） | 每个设备 `remove_memory` 后、`_EJ0` 前（每设备一次） |
| 机制 | vendor 驱动直接 `on_each_cpu` | ACPI 核心新增 `pre_eject` 回调 + vendor 驱动注册 |
| 修改文件数 | 1（`hisi_hbmdev.c`） | 3（`acpi_bus.h` + `scan.c` + `hisi_hbmdev.c`） |
| ACPI 核心改动 | 无 | `struct acpi_hotplug_profile` +1 字段、`acpi_scan_hot_remove` +5 行 |
| 满足固件时序要求 | ❌ SMC 在 _EJ0 之后 | ✅ SMC 在 remove_memory 之后、_EJ0 之前 |

|---|---|---|

## 5. 代码实现

### 5.1 include/acpi/acpi_bus.h — struct 扩展

```c
struct acpi_hotplug_profile {
	struct kobject kobj;
	int (*scan_dependent)(struct acpi_device *adev);
	void (*notify_online)(struct acpi_device *adev);
	bool enabled:1;
	bool demand_offline:1;
	void (*pre_eject)(struct acpi_device *adev);   /* v3 新增 */
};
```

### 5.2 drivers/acpi/scan.c — acpi_scan_hot_remove 修改

```c
static int acpi_scan_hot_remove(struct acpi_device *device)
{
	acpi_handle handle = device->handle;
	struct acpi_scan_handler *handler;              /* v3 新增 */
	unsigned long long sta;
	acpi_status status;

	/* ... offline 阶段不变 ... */

	/*
	 * Save the handler pointer before acpi_bus_trim() clears it, so
	 * pre_eject can still be invoked after memory removal but before
	 * device power-down (_EJ0).
	 */
	handler = device->handler;                      /* v3 新增 */

	acpi_bus_trim(device);

	if (handler && handler->hotplug.pre_eject)      /* v3 新增 */
		handler->hotplug.pre_eject(device);

	acpi_evaluate_lck(handle, 0);
	/* ... _EJ0 及后续不变 ... */
}
```

### 5.3 drivers/soc/hisilicon/hisi_hbmdev.c — vendor 驱动修改

```c
static void smc_flush_cache(void *info)
{
	struct arm_smccc_res res;

	arm_smccc_smc(HISI_HBMDEV_CACHE_FLUSH_SMC, 0, 0, 0, 0, 0, 0, 0,
		      &res);
	if ((int)res.a0 < 0)
		pr_warn("HBM SMC cache flush failed (ret=%d)\n",
			(int)res.a0);
}

static void hbmdev_pre_eject(struct acpi_device *adev)
{
	on_each_cpu(smc_flush_cache, NULL, true);
}

static void memdev_power_off(struct acpi_device *adev)
{
	struct acpi_device *child;

	list_for_each_entry(child, &adev->children, node) {
		const char *hid = acpi_device_hid(child);
		acpi_status status;

		if (strcmp(hid, ACPI_MEMORY_DEVICE_HID))
			continue;
		if (!child->handler)
			continue;

		child->handler->hotplug.demand_offline = true;
		child->handler->hotplug.pre_eject = hbmdev_pre_eject;   /* v3 新增 */

		get_device(&child->dev);
		status = acpi_hotplug_schedule(child, ACPI_OST_EC_OSPM_EJECT);
		if (ACPI_SUCCESS(status))
			continue;
		put_device(&child->dev);
	}
}
```

`state_store` 中 v2 的 `on_each_cpu` 调用已移除，SMC 调用移至 `pre_eject` 回调。

## 6. 风险点

1. **FID 必须与 HiSilicon HIP11 固件约定一致**：FID `0x83009000` **待固件团队最终确认。**
2. **ACPI 核心改动**：`struct acpi_hotplug_profile` 追加字段改变结构体大小。该结构体通过 `container_of` 从 `kobject` 访问，非直接导出给模块；`acpi_scan_handler` 实例均为静态声明（编译期确定大小）。`CONFIG_HISI_HBMDEV` 为 `bool` 内建，无导出符号影响。对 kABI 的影响：追加字段在结构体末尾，现有代码访问已有字段偏移不变，理论安全。
3. **`acpi_bus_trim` NULL 化 handler**：`acpi_bus_trim()` 在 line 2136 将 `adev->handler = NULL`。若不提前保存 handler 指针，`pre_eject` 回调无法获取。已在 `acpi_scan_hot_remove` 中通过 `handler = device->handler`（trim 前）解决，并有注释说明此不变量。
4. **`on_each_cpu` 开销**：`on_each_cpu(wait=true)` 同步 IPI 到所有 CPU。在多 CPU 系统上有延迟，但仅在 HBM offline 时触发（非热路径），可接受。
5. **SMC 粒度为每设备**：`memdev_power_off` 为每个 PNP0C80 子设备单独调度弹出，每个设备独立触发 SMC。若 N 个设备同时下电，SMC 广播 N 次。此行为正确——每个设备的内存独立移除，需独立刷新缓存。
6. **IPI 上下文约束**：`on_each_cpu` 回调运行在 IPI 上下文（IRQ 禁止）。`arm_smccc_smc` 是同步 trap 不睡眠，`pr_warn` 安全可用。无阻塞操作。

## 7. 验收标准

1. `make -j$(nproc)` 以 `~/tools/qemu_arm64_defconfig` + `CONFIG_COMPILE_TEST=y` + `CONFIG_HISI_HBMDEV=y` + `CONFIG_KVM=n` 编译零 error/warning
2. `scripts/checkpatch.pl --strict` 对 patch 零新增 warning/error/check
3. objdump 确认 `scan.o` 中 `acpi_bus_trim` → `blr pre_eject` → `acpi_evaluate_lck` → `acpi_evaluate_ej0` 调用链
4. objdump 确认 `hisi_hbmdev.o` 中 `hbmdev_pre_eject` → `on_each_cpu_cond_mask` + `smc_flush_cache` → `__arm_smccc_smc`
5. `state_store` 中不再有 `on_each_cpu` 调用（v2 残留清除）
6. `memdev_power_off` 中 `pre_eject` 回调注册在 `acpi_hotplug_schedule` 之前
7. 非 HIP11 平台不受影响（`hbmdev_init` 早期返回，`pre_eject` 不注册）
8. kABI：`pre_eject` 追加在结构体末尾，现有字段偏移不变
