目标：同 TGID、原 TID、原 task 的组内回滚；ORIGINAL 可以真正完成用户态退出/join/detach，同时保留内核任务。NEW 可以创建和最终销毁；触发回滚时仍存在的 NEW 在旧 mm 完成退出。一次成功恢复消耗一个检查点。

## 2. 首版支持契约

### 2.1 执行环境

- 原生 AArch64，不支持 compat/ILP32；独立 `CONFIG_TASK_CHECKPOINT_DEMO`，依赖 ARM64、MMU、FUTEX、PROC_FS，默认关闭，内建而非可卸载模块。
- 使用既有 QEMU ARM64 配置基线，保留 SMP、RSEQ、MEMBARRIER、LRU_GEN 和 PAC；不靠关闭这些配置绕过状态恢复。
- 首轮运行 CPU 关闭 SVE/SME（例如 QEMU `-cpu max,sve=off,sme=off`，实际属性在环境验证中确认）；禁用 MTE tagged memory 使用。内核即使编译这些能力，也必须检查任务运行态并拒绝不支持的状态。
- 面向受控 pthread 程序；PREPARE 要求 CAP_SYS_ADMIN、不为 PID namespace init、无 ptrace、无 seccomp/syscall user dispatch、无组退出/组停止，且无线程组外共享 mm/files/sighand 的任务。不以此提供对抗外部特权调试器的隔离。
- 原线程数上限 64，当前物理组任务数上限 128；超限返回 E2BIG/EAGAIN。保留 ORIGINAL 的任务数最多为初始线程数。
- 以本地 Buildroot 的 glibc 2.43 源码为首个线程库目标；运行前必须核对实际镜像库版本。测试在检查点前预热 pthread_exit/libgcc、动态链接及输出缓冲，避免用未声明的动态加载行为验证恢复。

### 2.2 内存和同步范围

- 支持私有匿名栈/堆/TLS及常规 ELF/共享库私有映射；代码文件在检查点期间保持不变。允许检查点后普通匿名 mmap/munmap/mprotect/brk 改变布局，恢复布局取检查点 mm。
- VDSO/VVAR 是架构特殊例外：按 ARM64 原有映射规则复制/重新关联，VVAR 的时钟数据不回滚。新增架构 VMA 校验函数识别实际 special mapping，不能按任意 VMA 名称放行。
- 拒绝共享可写、设备/PFN/IO（VDSO/VVAR 例外）、userfaultfd、hugetlb、VM_DONTCOPY、VM_WIPEONFORK、PROT_MTE 等不支持映射；普通 fork 的特殊语义不能默默改变快照。
- 建立安全点时不持有应用同步锁；robust list 为空、无 list_op_pending、无 PI owner/waiter 或 futex 等待。先处理本线程既有 task_work，再检查可保存条件。
- 原线程逻辑退出的保留路径同样要求 robust list 为空且无 PI 状态；若不满足，取消检查点并走原生退出，不进行不完整保留。首版不恢复“带 PI 内核所有权的锁”。
- ARMED 后支持同组普通非 PI futex 等待/唤醒和 pthread 同步；回滚前所有旧等待必须退出并到达返回用户态边界，旧等待队列不进入新 mm。不得只对运行线程执行 IPI 后就切换 mm。
- 外部文件/网络/数据库副作用、文件描述符表及文件偏移不恢复。运行期间只开放下述受控系统调用集合，异步 I/O、任意设备和动态装载不属于支持范围。

### 2.3 受控系统调用门禁

在 ARM64 调用分派前，对已登记任务执行 demo gate；未登记任务只有空指针快路径。允许集合限定为测试程序必需的原生系统调用类别：

| 类别 | 允许及校验 | 不支持行为 |
|---|---|---|
| 生命周期 | 符合共享契约的 clone/clone3 线程创建、exit、exit_group | fork/vfork、CLONE_VM 但非 CLONE_THREAD、unshare/setns/exec：返回 EOPNOTSUPP，保持检查点；正常 exit_group 解除保留并终止 |
| 内存 | 普通私有匿名 mmap、非 MTE mprotect、munmap、brk；madvise 仅常规匿名页回收提示 | mremap 首版拒绝；修改为特殊/共享映射、userfaultfd/页固定/远程内存操作拒绝 |
| 线程登记 | set_tid_address、set_robust_list、rseq，校验参数并保存本运行世代信息 | 不把当前登记覆盖检查点历史记录 |
| 同步/时间 | 非 PI FUTEX_WAIT/WAKE、WAIT_BITSET/WAKE_BITSET、REQUEUE/CMP_REQUEUE及对应超时；clock_gettime、nanosleep/clock_nanosleep、sched_yield、restart_syscall | PI/REQUEUE_PI/LOCK_PI2 类操作拒绝；其它 futex 子命令逐项默认拒绝 |
| 信号 | rt_sigaction/procmask/pending/sigreturn、kill/tkill/tgkill、getpid/gettid/getppid；sigaltstack | 保留态的普通线程定向信号 ESRCH；SIGKILL/STOP/CONT 例外 |
| 控制/输出 | 本 demo prctl、必要只读 prctl、预先打开 fd 的同步 read/write/writev、必要只读查询 | ioctl、io_uring、AIO、open/socket、权限/namespace/调度策略修改等默认拒绝，不假装恢复外部对象 |

实现采用明确逐项的 syscall/参数表，不使用“所有其它 syscall 大概无害”的默认放行。支持集合必须与实际 glibc 程序运行路径在⑥逐项对齐；不足时先修订本设计，不临时放行未知调用。CREATE/RESTORING 中 clone 拒绝或按既有 in-flight 预约完成受控退场，不发布无人管理的子任务。

外部 cgroup freezer/迁移、ptrace 及跨进程修改不是 syscall gate 能完整控制的行为。PREPARE 检查初始状态；相应内核入口对管理中的组拒绝新 ptrace 附加、cgroup 迁移/冻结，选择 EBUSY 而不是在外部锁内取消并等待 HELD。具体 hook 及发布互斥见第5节。不承诺抵御外部特权进程绕过支持接口直接修改内存。

## 3. 用户接口

在 `include/uapi/linux/prctl.h` 增加实验命令 `PR_TASK_CHECKPOINT_DEMO = 0x43504b54`（实现前再检查冲突，不申请通用 syscall 号）。调用 `prctl(PR_TASK_CHECKPOINT_DEMO, op, arg, 0UL, 0UL)`；安全模块仍先经过现有 security_task_prctl。

| op | arg | 返回与语义 |
|---|---|---|
| PREPARE=1 | 预期原线程数 | 枚举全部线程并建立 COLLECTING，返回正的 epoch；重复有效事务 EBUSY、人数不匹配 EAGAIN，不创建 mm 快照 |
| ARRIVE=2 | epoch | 每个初始线程调用一次，阻塞到全员到齐；初次成功返回 0，恢复后从此调用位置返回 1；重复到达 EALREADY，旧 epoch ESTALE |
| DROP=3 | epoch | 取消 COLLECTING/ARMED、释放快照并结束 HELD；等待解除保留完成后返回 0；RESTORING 中 EBUSY |
| STATUS=4 | epoch | 返回确定的公开阶段枚举，不能暴露内部指针；不存在/旧 epoch ESTALE |

所有未使用参数必须为零。epoch 使用单调、限定为 LONG_MAX 内的正数，溢出失败而不是复用旧值。一次性是每个快照消费一次；消费后可重新 PREPARE。

推荐用户流程：先创建工作线程，再 PREPARE 并把 epoch 通过用户 barrier 发布给所有线程；各线程在不持锁的位置 ARRIVE。ARRIVE 进入内核前锁和 barrier 必须已经释放。全员到齐后才复制 mm。不能由 PREPARE 自己无限阻塞，使其它线程拿不到 epoch。

COLLECTING 从 PREPARE 发布起到全员 ARRIVE 并发布快照的协调期限为 5 秒；不齐则所有已到达者返回 ETIMEDOUT，尚未到达者之后返回 ESTALE。首次和最后一次到达均复查期限，复制完成后也复查再发布；分配本身不承诺在故障下具有硬实时上界。

## 4. 内核结构与持有关系

新增类型，名称作为实现约定：

```c
struct task_ckpt_group;   /* 一次检查点事务、引用、快照和计数 */
struct task_ckpt_member;  /* ORIGINAL/NEW身份与当前阶段 */
struct arm64_ckpt_state; /* 用户寄存器、TLS、FP、PAC等 */
```

group 保存 epoch、phase、截止时间、waitqueue、original 成员数组、当前成员链表、arrived/parked/switched/new_pending/inflight_clone 计数、逻辑活动计数、错误码、old_mm、snapshot_mm、LRU注册状态以及历史信号处置。

member 保存 group 引用、task 引用、ORIGINAL/NEW、ACTIVE/EXIT_CLEANUP/HELD/QUIESCENT/SWITCHED/DEPARTED、是否计入逻辑活动数、历史架构现场/信号屏蔽字/altstack/clear_child_tid/robust/rseq 登记、退出码。NEW 不分配架构历史镜像。

利用 KABI 保留槽存放指针：`signal_struct` 的空闲槽 1 存 group 指针，`task_struct` 的空闲槽 4 存 member 指针；CONFIG 关闭时保持 KABI_RESERVE。不能直接扩大下游核心结构。子任务复制时必须清除继承的 member 指针，成功发布时才设置 NEW。

signal 指针持有 group 引用；每个已登记 member/执行中的 helper 都有明确引用。异步快路径通过 RCU 读取指针并 refcount_inc_not_zero；摘除指针后经 RCU 延迟释放，不能在 get_signal/task_work 中用裸指针越过解锁。

ORIGINAL 数组持有 task 引用至事务结束，防止引用对象释放；**任务真正不退出来自保留协议，而非这个引用**。NEW 在物理退出解除登记，不因 group 对它的观察引用延缓正常退出流程。

## 5. 状态机与锁序

组状态：`COLLECTING → ARMED → RESTORING → CONSUMED`；取消走 DISARMING；不可恢复/整组退出走 TERMINATING。CONSUMED 的事务对象可因 helper 引用尚存而继续占内存，但不能再次恢复。

| 事件 | 动作 |
|---|---|
| PREPARE | 在成员发布受控窗口验证无 in-flight clone，再枚举并登记当前全部成员 |
| 原线程 COLLECTING 中退出 | 取消采集、唤醒已到达线程，再走原生退出 |
| ARMED ORIGINAL exit | 进入 EXIT_CLEANUP；完成地址安全处理/通知后成为 HELD |
| ARMED NEW exit | 逻辑退场并执行原生 do_exit；物理退场另记一次 |
| ARMED 默认 SIGABRT | siglock 下唯一竞争到 RESTORING，选择 ORIGINAL 协调者 |
| RESTORING NEW 退出 | 内部移除，不按“最后活动线程归零”取消恢复 |
| ARMED 正常业务活动数归零 | TERMINATING，放弃检查点、走原生整组退出 |
| DROP | DISARMING，快照不可再消费；唤醒 HELD 真正退出，确认退场后摘除事务 |
| SIGKILL/exit_group/其它致命退出 | TERMINATING 优先，任何阶段不得恢复用户代码 |

使用 `sighand->siglock` 保护 phase、member状态、计数及信号决策，避免另造相反锁序。group 的 sleepable `op_mutex` 只序列化协调者的复制/释放，不由参与线程取得，不跨等待屏障持有。

允许已有顺序 `tasklist_lock → siglock`；成员发布/移除在既有 fork/exit 临界区内完成，不从持 siglock 的路径反向申请 tasklist_lock。需要枚举时释放 siglock 后取得 tasklist_lock，再重查 phase/epoch。

mmap锁、task_lock、rq锁、futex清理均在不持 siglock 时执行。先发布中间态，再解锁处理，再以 epoch/phase 重查后确认完成。无自旋锁、RCU读锁或 op_mutex 跨全组等待。waitqueue 条件在锁内发布，解锁后 wake，使用等待原语而非裸 schedule 防止丢唤醒。

clone 在开始复制前用 siglock 预约 inflight_clone；PREPARE 发现已有预约则 EAGAIN。COLLECTING 新预约拒绝。已 ARMED 的预约在恢复发生后仍可完成发布，但子任务必须先登记 NEW 并在返回用户态前退出；父线程到返回边界再参与恢复。发布失败、cgroup拒绝等路径均撤销预约。

### 外部操作与 PREPARE 的互斥

新增仅用于登记窗口的全局 `ckpt_enroll_rwsem`。PREPARE 在预分配完成后取 write，期间只做 RCU 状态读取和 tasklist_lock→siglock 枚举/发布，不取 cgroup_mutex、freezer_mutex、cred_guard_mutex，也不等待其它线程到达检查点；发布后立刻释放。

外部操作在提交前用 **down_read_trylock** 取 read，失败立即返回 EBUSY，绝不持 cgroup/cred_guard/freezer 外层锁阻塞等待登记锁；取得后检查全部目标任务/子树内有无非空检查点登记，存在则 EBUSY；否则持 read 完成原生提交再释放。即使已有PREPARE写者排队，也不能形成“clone持read等cgroup，cgroup持mutex等read，写者等clone”的等待环。具体位置：

- ptrace_attach 在 cred_guard_mutex 内、tasklist_lock 外取得 read；在 tasklist临界区、设置 task->ptrace 前检查目标登记。ptrace_traceme 同样在 tasklist_lock前获取read。PREPARE 不取cred_guard_mutex，避免反序。
- cgroup_migrate_execute 在调用 can_attach 和迁移提交前取得 read，扫描其 tset 的全部迁移任务；外层已有 cgroup_mutex，但 PREPARE 不取得此mutex。
- cgroup v2 的 cgroup_freeze_write 在 cgroup_kn_lock_live 后、cgroup_freeze前取read，检查目标所有后代任务；保持至freeze返回。thaw同样序列化，但不因已有检查点拒绝解除冻结。
- cgroup v1 的 legacy_freezer.c:freezer_write 在调用 freezer_change_state 前取read并检查整个后代css集合，保持至原生操作结束。PREPARE检查祖先freezing状态，拒绝已经处于冻结中的任务。

外部门禁只读登记状态，不在这些外层锁中等待恢复或释放，不反向申请op_mutex。外层mutex→enroll_tryread是非等待边；唯一可以阻塞的enroll读获取是copy_process包装的入口，必须位于fork内部cgroup锁之前。PREPARE为enroll_write→tasklist→siglock，不取cgroup或其它外层mutex。CPU热插拔/PM冻结不属于支持的运行环境，demo不提供系统休眠恢复承诺。

## 6. 保存与 mm 快照

ARRIVE 每线程先排空本线程已支持的 task_work，保存用户返回帧、实际 TLS/FP 状态、信号等，设置 QUIESCENT；整个保存点必须在当前任务上下文执行。采集时若出现 SIGKILL、组停止或不支持状态则取消。

最后到达者在全组停驻后调用新增内部 `task_ckpt_dup_mm(owner, oldmm)` 包装现有 dup_mm。包装仍放在 kernel/fork.c，可调用静态内部逻辑，不向模块导出；先做支持VMA和资源限制检查，再复制，失败用原 mmput 清理。不得 memcpy 整个 task/thread_struct 作为快照。

group 对 old_mm 持一份 mmget，snapshot_mm 的初始 mm_users=1 由 group 所有。复制后的新 mm 有独立 CID/页表/上下文；membarrier_state 显式保存检查点值，不对每个恢复线程执行 membarrier_exec_mmap 清零。

standby snapshot 不反复加入 LRU_GEN 的 mm 链表；恢复提交前由协调者注册一次，失败释放以标准 mmput 路径配对。普通 fork仍使用原路径。拒绝特殊映射，不让 DONTCOPY/WIPEONFORK 或异步 pinned 页改变历史语义。

## 7. ORIGINAL 逻辑退出与 leader

raw exit 进入 do_exit 前调用 `task_ckpt_exit(regs, code, &return_value)`。未登记或非保留条件返回 PASS，让原 do_exit 继续；仅成功恢复时返回 RESTORED，系统调用返回值取检查点的 1。

ORIGINAL 正常逻辑退出：

1. 发布 EXIT_CLEANUP；确认组未在真正终止。
2. 在旧 mm 核对 robust list 为空且无 pending、无 PI，处理允许的 task_work。若不满足则 DISARMING，全组不再承诺回滚，走自然退出，不把复杂 futex_state 从 DEAD 重新初始化。
3. 在当前线程撤销 rseq 登记及其事件状态，摘除当前 robust_list 登记；空列表不会产生 OWNER_DIED 用户写入，futex_state 保持 OK。
4. 保存并清除当前 clear_child_tid 清理责任，按原生规则对有效地址清零并 futex wake。通知发生后不再访问旧用户栈/TLS，最终 do_exit 不重复写此地址。
5. 逻辑活动数只减一次，进入 HELD。原生 live/quick_threads/nr_threads、PF_EXITING 不变，不调用 exit_signals 或 exit_notify。
6. HELD 被恢复请求唤醒则进入恢复屏障；被 DROP/终止唤醒则用原退出码走正常 do_exit，跳过已完成通知的运行世代登记。

目标 glibc 的工作线程依赖内核最后通知；初始线程已在用户态提前通知，其生命周期另证：初始化将 stack_mode 设为 USER，`nptl-stack.c` 不 unmap 这块用户栈，`_dl_deallocate_tls(tcb,false)` 仅释放动态 TLS/DTV，不释放 TCB 本体（`elf/dl-tls.c:728-745`）。内核 rseq、robust_head 和 clear-child-tid 指向静态 TCB 部分，不读取 DTV。本 demo 不支持应用自行提前 unmap 初始线程仍在执行的栈/TCB；安全点和逻辑退出空 robust 前提均检查。因而不能把“动态 TLS 被释放”直接等同于“内核登记的 TCB 已被释放”。

leader 的 HELD 状态保留原 task/TGID，可被协调者直接唤醒恢复；不交换 PID，不重建 leader。main 返回/exit_group 是终止，不截留。所有逻辑活动线程结束时不让整个进程只剩永远等待的 HELD。

## 8. SIGABRT、停驻和 NEW 退场

在 get_signal 已选中 SIGABRT 默认动作、释放 siglock 进入 fatal/core前调用恢复入口。争夺 phase 在 siglock 下完成，随后解锁协调。不得在已设置 PF_SIGNALED、core_state 或 SIGNAL_GROUP_EXIT 后回滚。

协调者固定为 ORIGINAL leader，发起者可以不同。接管在 leader 确认进入内核恢复点后才算成功。NEW 发起者在接管前保持引用和旧 mm，不以发一次唤醒代替交接；超时或终止竞争则整组失败终止。

所有 ORIGINAL 通过三种入口会合：ARRIVE 等待栈、raw exit HELD 等待栈、ARM64 返回用户态边界。运行中的线程用 notify 标志及 kick/wake促使返回边界；可中断系统调用先自行退栈，不能从中途强制换 mm。每个参与者先运行旧 task_work、取消旧系统调用重启，再报告 QUIESCENT。无法停驻的线程导致失败，不允许协调者替它远程改 mm。

NEW 收到内部 REMOVE 原因后在本任务上下文调用原生 do_exit(0)，不向它发送具有整组语义的 SIGKILL。OLD 用户地址清理在 exit_mm_release 前后完成；物理成员移除在 release_task/__exit_signal 的既有临界区报告 DEPARTED。协调者等待全部 NEW 物理退场和 in-flight clone归零后才进入 mm 切换。

当所有 ORIGINAL 原先都 HELD、唯一活动 NEW 发起 abort 时：RESTORING 已经建立，NEW 清理归零不建立正常组退出；leader 已接管，依旧恢复全部 ORIGINAL。真正 SIGKILL/组退出始终可打断这一过程。

## 9. 每线程切换与提交

### 9.1 两个屏障

第一屏障：全部 ORIGINAL QUIESCENT，全部 NEW DEPARTED，无 clone预约，旧用户内存访问及非允许工作已结束。协调者再次校验 VMA及架构状态，没有把不支持状态带过门禁。

第二屏障：全部 ORIGINAL 已切换 mm、恢复线程登记和架构现场。此时之前不允许任何 ORIGINAL 执行用户代码。协调者在 siglock 下检查无 TERMINATING 后提交 CONSUMED，恢复逻辑活动数为原线程数，取消所有保留责任。

### 9.2 引用账本

- group 持 old_mm 的 1 份引用，直到所有 NEW 退场、全部 ORIGINAL 已放弃旧 mm 后再释放。
- snapshot 初始 1 份group引用；为 N 个 ORIGINAL 预先增加 N 份引用，分别在每线程安装新 mm 时转移给任务，不能安装后再补引用。
- 每线程记录是否已转移；失败时由 group 释放未转移的预留引用，已转移引用由任务正常退出释放。
- 提交后释放 snapshot 的group引用，不能释放已成为进程活动地址空间的 N 份任务引用。对象上的指针置空标记责任已转移，析构不再重复 mmput。
- 原 mm 的任务引用由每线程本地切换后 mmput；group额外引用保证不会在其他线程仍需旧 mm 时销毁。

### 9.3 本地切换原语

新增 `task_ckpt_switch_mm_current(newmm)`，仅 current、已经 QUIESCENT 时调用：

1. 保存 oldmm；执行与现有 before_execve 同契约的 CID 释放，仅作用 current，不触碰 PF_EXITING。
2. 在 task_lock 和本地中断保护下完成 membarrier所需前置内存屏障、current->mm/active_mm 更新，调用 activate_mm(old,new) 更新 ARM64 ASID/TTBR0 及 saved TTBR0，再更新当前 rq 的 membarrier_state。
3. 解锁/恢复中断，在新 mm 上执行 after_execve 的 CID重新登记和 lru_gen_use_mm；mm_init_cid 只在新 mm 初始化阶段一次，不每线程重置共享CID表。
4. 按 owner和引用规则更新旧mm归属并放任务旧引用。不得调用 exec_mm_release，防止无意触发旧 clear_child_tid/futex 副作用。

CID 可复用现有 before/after_execve 内容，但在调度头文件提供命名明确的新 wrapper，不将它们当作完整 exec。LRU_GEN add由协调者一次执行，不在每线程重复。membarrier使用保存值和 update_current_mm，而非重复清零。

## 10. ARM64 与用户地址登记恢复

新增 `arch/arm64/kernel/task_checkpoint.c`：

- `arm64_ckpt_save()`：复制用户寄存器字段，调用 fpsimd_preserve_current_state、tls_preserve_current_state；保存基础 FP/SIMD、FPMR（存在时）、TLS、用户 PAC keys及用户SCTLR相关值；拒绝活动SVE/SME、tagged MTE、不支持调试状态。绝不复制 cpu_context 或内核 PAC keys。
- `arm64_ckpt_restore()`：恢复用户字段并通过 valid_user_regs 校验，设置 x0=1、forget_syscall，restart_block.fn=do_no_restart_syscall；恢复实际 TPIDR、FP状态并 fpsimd_flush_task_state，用户 PAC keys用架构现有安装机制恢复；内核 APIA/PAC 的现有内核密钥不变。
- generic登记恢复：历史 blocked/saved_sigmask/altstack、clear_child_tid、空 robust_list 指针、rseq地址/长度/签名。rseq cpu/node/mm-cid 值须按当前CPU在返回用户态前更新，不回放旧 CPU 编号；不得把旧运行世代 rseq event_mask原样恢复造成指令重定向。
- 组共享 sighand action 在所有线程停驻时一次恢复。消费引发事务和本事务窗口内已归并的 SIGABRT；普通非致命信号若无法按支持契约保留，则取消/失败，不能静默清空所有 pending；SIGKILL不清除。

ARM64 get_signal调用者增加显式 restored结果。generic get_signal 用本次调用局部结果（如 ksignal 内受配置保护的字段）标识恢复，do_signal立即返回，跳过旧 retval/restart_addr 和 restore_saved_sigmask。返回用户态通用guard恢复时刷新 thread_flags，不沿用恢复前局部标志。

raw exit分流恢复后让系统调用C返回值为恢复x0，避免 invoke_syscall再次覆盖成退出码。ARRIVE的本次返回也使用相同返回约定。

## 11. HELD 的信号和作业控制

- wants_signal跳过 HELD普通信号接收，retarget_shared_pending跳过HELD并转向活动成员；进入HELD时参与重定向，不能让共享pending滞留在错误target。
- tgkill/tkill等普通定向信号在权限检查后对HELD返回ESRCH；SIGKILL/SIGSTOP/SIGCONT明确例外，仍执行其组级语义。
- HELD的等待可被终止、restore/drop控制唤醒。组停止分配JOBCTL_STOP_PENDING时跳过已经静止HELD；线程在既有组停止过程中转HELD需在siglock下完成它已有的participation并更新group_stop_count，CLD_STOPPED通知仍由现有协议单次产生。CONT不让HELD返回用户态。
- 真正终止时先发布TERMINATING，唤醒所有HELD及协调等待；原生exit_group/SIGKILL再完成原生记账。恢复中部分线程已经换mm仍允许各自按当前mm真正退出，绝不返回混合现场用户态。
- 其它默认致命信号不触发恢复；在core同步前先放弃检查点并确保HELD不阻塞coredump的线程退出会合。

## 12. DROP、失败和释放

| 场景 | 处理 |
|---|---|
| 参数/权限/不支持状态 | EINVAL/EPERM/EOPNOTSUPP，未发布有效快照 |
| COLLECTING缺员、成员退出、普通信号打断 | 取消，唤醒已到达成员返回明确错误，释放已有记录和mm |
| dup_mm或预分配失败 | ENOMEM，不改变原地址空间，snapshot按原释放路径清理 |
| ARMED出现不支持的逻辑退出条件 | 取消检查点，完成HELD真实退出，当前退出继续原生行为；不得宣称回滚仍有效 |
| 恢复超时/NEW交接失败/切换失败 | TERMINATING，整组SIGKILL；父进程可观察，不返回部分恢复现场 |
| 外部SIGKILL/exit_group/默认其它致命信号 | 保留原终止原因及原core语义，释放保留，不自动替换成回滚失败结果 |
| DROP | 协调释放并等待HELD离开；不能DROP返回后仍留永久保留任务 |
| 恢复成功 | CONSUMED，全体原线程回到ARRIVE返回1；第二次SIGABRT走原生终止 |

释放职责分离：task成员摘除只发生一次，group最终析构不等待线程；需要等待的动作由协调者先完成。最后一个member离开/最后一个helper引用释放后才可销毁group，不能通过task引用和group引用构成不可解循环。RCU回调只做非睡眠释放部分，mmput/需要睡眠的释放在普通工作上下文完成。

## 15. 审核修订：精确协议（优先于前文概述）

### 15.1 登记前 clone

仅在已有group中计数不能覆盖登记前的复制。因此把现有copy_process实现改名为内部函数，保留公共copy_process签名作为包装：在调用内部函数前取ckpt_enroll_rwsem读锁，覆盖全部参数校验、复制、任务发布及失败路径，返回前释放。包括无检查点、CLONE_THREAD以及组外共享mm/files/sighand创建，都经过该包装；不只包装kernel_clone。CPU启动期idle创建可按系统未运行阶段走无并发初始化分支。

PREPARE写锁与所有在途copy_process互斥。拿到写锁后，所有此前开始的复制均已成功发布或失败；此时枚举实际成员并检查组外共享，再在tasklist→siglock下发布COLLECTING，是登记线性化点。新的复制在写锁释放后进入，发现COLLECTING则返回EBUSY。因此不存在“未预约子任务在发布事务后悄悄入组”的窗口。

ARMED内的复制仍登记inflight_clone，保证与RESTORING竞争时已预约子任务完整纳管。公共包装持读锁期间不等待检查点事务，PREPARE写锁期间不取fork内部会持有的cgroup等mutex。

### 15.2 默认SIGABRT分流及归并

在siglock内完成dequeue后默认动作判断及phase分流；需要进入恢复时取得本事务引用，再释放锁。所有默认SIGABRT分流结果如下：

| phase | ORIGINAL | NEW |
|---|---|---|
| 无事务/COLLECTING/DISARMING/TERMINATING/CONSUMED | 原生默认终止；COLLECTING先取消采集 | 同左 |
| ARMED | 唯一转换RESTORING，唤醒leader并参与屏障 | 唯一转换RESTORING，等待leader接管，再REMOVE |
| RESTORING | 已dequeue的败选触发不进入fatal/core，加入同一屏障 | 加入同一事务并REMOVE，不进入fatal/core |

SIGABRT只有默认动作触发恢复；自定义handler/ignore仍按原生行为。归并范围是该事务从ARMED首个默认触发到最终提交之间的SIGABRT：包括已dequeue的败选者，以及private/shared pending中的SIGABRT（包括被屏蔽者）。在全部参与者停驻后、提交CONSUMED前，协调者持siglock，用按信号mask清理的原语释放这些pending的sigqueue记录，而不清理其它信号。提交CONSUMED和归并截止在同一个siglock临界区；之后新入队SIGABRT按恢复后的处置正常处理。

仍未到屏障的已dequeue调用者阻止全组提交，因此不会出现其持旧默认触发在提交后又误入fatal的情况。非ABRT普通信号在COLLECTING中取消并返回EINTR，按原队列正常递送；在RESTORING中导致失败终止，绝不静默丢弃。SIGKILL和已有组退出始终优先。

### 15.3 返回入口与jobctl

运行线程停驻通过set_notify_signal(task)触发（会唤醒可中断等待并kick运行CPU），不把虚假的SIGKILL当作停驻请求。HELD使用独立waitqueue唤醒。

在ARM64 do_notify_resume的本轮非NEED_RESCHED分支、DAIF恢复后、任何旧信号/UPROBE/rseq用户工作前调用task_ckpt_resume。函数先检测真正终止和STOP冲突，在旧mm排空允许的task_work，再处理RESTORING停驻。正常ARMED仅返回，不阻止原生get_signal/jobctl。restore完成时刷新thread_flags继续新现场，不使用旧局部值。get_signal内部已dequeue的ABRT走15.2，恢复结果使do_signal立即跳过旧restart/mask收尾。

| 阶段 | STOP（含正在进行的group stop） | CONT |
|---|---|---|
| COLLECTING | 取消采集，唤醒ARRIVE返回EINTR，然后原生get_signal处理STOP | 不吞信号；正常原生CONT处理，若打断采集则取消 |
| ARMED | 原生组停止；HELD不增加待停止计数，转换HELD时结清已有participation | 原生继续活动线程，不使HELD回用户态 |
| RESTORING | 已停止成员、未结清JOBCTL_STOP_PENDING、或本阶段新STOP均令恢复失败并SIGKILL整组，不越过停止直接返回用户态 | 不清STOP状态，不把CONT当作完成屏障；正常组控制处理；SIGCONT作为协调期非ABRT信号使本次恢复失败 |

恢复开始时在siglock下检查所有成员的stopped/jobctl及STOP pending；每个resume入口、屏障提交前再次检查。原生STOP路径在调用do_signal_stop前同样检测RESTORING并进入失败终止。此策略允许恢复/作业控制冲突时失败退出，而非试图在⑤实现完整可回放jobctl；非恢复阶段仍须保持正常STOP/CONT。

### 15.4 系统调用逐项约束

无事务走原生。ARMED和尚未到齐的COLLECTING使用下面的完整白名单，**COLLECTING唯一额外限制是禁止clone/clone3**，所以其它未到达线程的内存变化在最后ARRIVE前仍可完成；最后全组停驻后才快照。RESTORING不进入新的用户态调用，NEW直接REMOVE。未列项目一律EOPNOTSUPP且保持事务不变；预检查不修改参数或用户内存。正常exit_group例外是终止而非拒绝。

- 无额外约束：getpid/gettid/getppid/getuid/geteuid/getgid/getegid、clock_gettime、clock_getres、gettimeofday、nanosleep、clock_nanosleep、sched_yield、restart_syscall、rt_sigaction、rt_sigprocmask、rt_sigpending、rt_sigreturn、sigaltstack、kill、tkill、tgkill、exit、exit_group、set_tid_address、set_robust_list、rseq、read、write、writev、fstat、newfstatat、lseek、getrandom（flags不得含GRND_INSECURE以外未知位，实际参数仍由原生校验）。read/write等外部效果不回滚。
- futex：按FUTEX_CMD_MASK仅允许WAIT、WAKE、WAIT_BITSET、WAKE_BITSET、REQUEUE、CMP_REQUEUE；允许PRIVATE_FLAG和CLOCK_REALTIME的原生组合；其它命令EOPNOTSUPP，包括所有PI类。futex_time64在原生AArch64不存在，不引入compat接口。
- clone/clone3：必须同时有CLONE_VM|CLONE_FS|CLONE_FILES|CLONE_SIGHAND|CLONE_THREAD|CLONE_SYSVSEM|CLONE_SETTLS；仅可附加CLONE_PARENT_SETTID|CLONE_CHILD_SETTID|CLONE_CHILD_CLEARTID。exit_signal必须0。禁止PIDFD、PTRACE、UNTRACED、VFORK、INTO_CGROUP、namespace等其它flag；clone3要求set_tid_size=0、set_tid=0、cgroup=0；结构未知尾部按原生copy_clone_args_from_user校验。未设置CLONE_PIDFD时pidfd字段按原生语义忽略，因为目标glibc 2.43的pthread_create会在未使用PIDFD时仍填写该字段为pd->tid地址，禁止实际PIDFD操作由flags门禁保证。非法组合EINVAL，禁止flag为EOPNOTSUPP，COLLECTING为EBUSY，当前人数达128为EAGAIN。
- mmap：flags仅MAP_PRIVATE|MAP_ANONYMOUS，可附加MAP_FIXED|MAP_FIXED_NOREPLACE|MAP_STACK|MAP_NORESERVE；fd必须-1，offset必须0；prot仅READ|WRITE|EXEC及PROT_NONE。mprotect的prot采用同一限制；munmap/brk按原生地址校验。禁止映射即EOPNOTSUPP，无隐式失效。
- madvise：仅MADV_NORMAL、RANDOM、SEQUENTIAL、WILLNEED、DONTNEED、FREE；其它advice为EOPNOTSUPP。mremap拒绝。
- prctl：仅本DEMO命令、PR_GET_NAME、PR_GET_DUMPABLE、PR_GET_PDEATHSIG、PR_GET_NO_NEW_PRIVS、PR_GET_TID_ADDRESS、PR_GET_TAGGED_ADDR_CTRL、PR_PAC_GET_ENABLED_KEYS；原生命令保留原参数校验。禁止SET类、PAC重置、SVE/SME/MTE配置更改等。

同类名称如实际该内核未定义则不编入表，不为其它架构号提供别名。clone3及mmap等需要复制/解析用户参数的检查必须在原生参数已复制后执行，防止检查一次用户结构后原生再次读取造成TOCTOU；syscall入口只做静态号筛选，子命令/flags放在实际分派点。陌生参数不靠⑥测试临时决定是否放行。

## 16. 流程更新

用户要求后续无需再逐阶段确认。因此保留代码/设计审核和测试门禁，审核通过后自动进入下一阶段；不等待用户确认，不创建未经明确要求的git提交。当前不把未运行的设计标为已验证功能。

## 17. 实现收敛记录

实际实现使用固定ORIGINAL数组及task上的原成员指针；NEW由共享signal事务、空原成员指针及cloning/newborn计数识别，不为正常销毁的NEW长期分配历史记录。siglock下状态转换、唯一最后ARRIVE和固定leader保证唯一重操作，不再增加op_mutex；操作本身持group引用保证取消并发时对象不被释放。

DROP以原线程exit_state确认必要清理，允许leader保持原生僵尸，不等待PID消失。恢复失败先在siglock下建立真正SIGKILL终止状态，再解除/唤醒事务；已有组退出或core状态不被额外SIGKILL覆盖。exit_group建立原生退出后再解除保留，core路径依靠原生协调唤醒退出成员。测试配置新增可观测计数、raw exit暂停和四个一次性故障注入点，正常功能配置不包含这些测试接口。

这些收敛不降低已确认的多线程动态生命周期和同身份恢复目标。完整测试目标尚未全部执行，实际覆盖率与差距单独报告，不冒充生产级通用回滚。
