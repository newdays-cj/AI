# 覆盖率：实际结果与设计差距

## 实测范围

最终启用构建、14场景×100轮、10边界案例、v1/v2外部控制及独立KUnit之后采集。
新增三个C文件：47/47函数命中，644/701行（91.9%），427/660分支方向（64.7%）。
对应证据为tests/coverage.info、lcov.log、coverage_summary.txt及gcov/coverage_html。
统计排除头文件重复归并，**不代表所有旧文件修改函数的全覆盖**。KUnit断言失败方向、
GCC生成的异常分支、硬件及不可达防御分支均不能冒充正常已覆盖路径。

逐函数真实名称、源文件行号及命中次数由pack生成`tests/函数覆盖明细.md`；全部零计数或
未执行分支方向（含源码表达式）列入`tests/uncovered-branches.csv`。不将这些方向统一
宣称为不可测试，也不声称达到了设计阶段的100%全分支目标。

## 后续质量目标

硬件、不可达或破坏性路径逐项给出例外理由。当前保留了该缺口，没有将“函数100%”
替换成“分支100%”结论。
