# 实现自审及审核记录

本文件保留提交前自审记录。用户随后要求本地提交并归档，正式提交与新的补丁校验信息
见00-交付清单.md、09-提交归档记录.md及COMMIT.txt；不将历史“未提交”描述用作当前状态。

## 功能与生命周期

已检查配置关闭stub、独立KABI槽、PREPARE/ARRIVE/DROP、原任务保留、NEW移除、两道恢复屏障、mm预留引用转移、信号和jobctl，以及真实终止优先级。

实现采用ORIGINAL固定数组与task指针；NEW通过共享signal事务及空ORIGINAL指针识别，复制预约/物理退场计数保证纳管，无需为每次临时线程创建保留记录。用siglock下phase转换、唯一最后到达者及固定leader代替额外op_mutex；重操作持自身group引用，不持siglock等待。

实际代码与设计的必要修订已记录：未设置CLONE_PIDFD时忽略pidfd字段以兼容glibc；五秒期限从PREPARE成功发布起算；DROP以exit_state确认必要原生清理完成，允许leader保持僵尸。没有把保留引用等同于保留任务，也没有从do_exit尾部复活任务。

## 修复的审核发现

1. leader HELD后的DROP不能等待PID消失：改为exit_state，加入专门回归。
2. 进入HELD时的共享pending可能滞留：同一siglock内重定向，并在原生retarget遍历中排除HELD；加入raw exit暂停/共享ABRT确定性竞态。
3. 恢复前架构状态需复查：每个原线程QUIESCENT前和恢复入口均检查SVE/SME/MTE/debug。
4. 已有异步状态：拒绝AIO mm表、io_uring任务/文件；实际测试覆盖PREPARE或ARRIVE早期拒绝。
5. 恢复失败必须先发布真实终止信号，再唤醒/解除事务；避免部分切换线程在终止信号建立前返回EL0。
6. 原生exit_group先建立组退出及唤醒，再解除保留；core路径保留原生core协调，避免过早解除恢复屏障。
7. GCOV SMP非原子更新曾产生负分支计数：仅GCOV+GCC下启用atomic更新，并禁用AArch64 outline-atomics，避免依赖内核不可用的libgcc辅助函数。

移除了未参与逻辑的字段和恒为false的辅助函数参数，没有TODO或占位实现。

## 并发检查

- 复制全程enroll读锁；PREPARE发布写锁；外部持锁路径仅tryread，失败EBUSY。
- 任务关系已有tasklist→siglock顺序，不持锁进行全组等待、分配或mmput。
- 原任务TID关联不解除；NEW本任务执行do_exit，在__exit_signal物理退场后才允许切换。
- 真实SIGKILL/组退出先于恢复，内核调用栈不回滚。对象RCU后转workqueue析构。
- DROP与恢复争夺在siglock下决定，不允许DROP取消正在切换的事务。
