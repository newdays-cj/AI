# 阶段④方案审核

## 结论

已调用 Momus 审核 `04-方案对比.md`，参考需求、架构分析及当前源码，结果为**条件通过，推荐 A：只保留检查点原线程**。

审核认为两种保留策略可作为阶段④候选，当前未发现方案级硬矛盾；这不是已编码、编译或运行验证的结论。

## 已修订的三个条件

1. 只有正常运行期间最后逻辑活动线程退出才触发正常整组终止。RESTORING 清理 NEW 不适用该归零规则，已接管的 ORIGINAL 继续事务，避免“所有 ORIGINAL 已 HELD、唯一 NEW 触发 abort”时错误终止。
2. 区分内核 clear-child-tid 通知与 libc 初始线程提前发布的 joinstate 通知。补充初始线程 set_tid_address、USER 栈、robust/rseq 登记的源码依据，并列为⑤单独生命周期证明门槛。
3. 对 HELD 线程定向发送普通信号的 ESRCH 建议明确排除 SIGKILL/SIGSTOP/SIGCONT，保留它们的组控制语义。

## 进入⑤仍需证明

- mm、上下文和原生计数的组级切换、资源持有和失败清理。
- robust/futex_state/rseq/task_work 及提前退出通知的用户地址安全。
- NEW 发起者到 ORIGINAL 的交接确认，以及 NEW 旧 mm 清理完成屏障。
- SIGKILL、STOP/CONT、检查点释放和最后业务线程退出的竞态闭环。
- 不支持操作的准确识别、拒绝/失效策略。
