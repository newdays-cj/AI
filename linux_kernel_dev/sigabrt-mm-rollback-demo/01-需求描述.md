# SIGABRT 内核地址空间回滚 demo

## 状态

用户已明确：ARM64 架构、多线程、一次性检查点，必须支持检查点后线程创建和销毁；接受协作建立检查点安全点。固定线程集合建议已被否决。接口和具体实现留待调研、设计阶段确定。

后续用户提出检查点有效时暂不真正销毁 task，并要求继续。当前按“允许用户态线程逻辑退出，内核任务可延迟销毁”进入候选方案论证；原有不允许以停驻冒充 join/销毁的限制，调整为必须完成线程库可观察的退出通知，不能仅阻塞 pthread_exit。

## 背景与原始诉求

用户希望在 OLK-6.6 中开发 demo：进程 A 到达 X 后建立检查点，继续运行；发生 abort 时进入内核，将当前地址空间替换为检查点状态，并从 X 继续执行。恢复应在同一进程实例内完成，而非由监控程序重新启动进程或通过 CRIU 恢复另一个进程。

仅替换 current->mm 不满足执行正确性，需求同时包含用户态执行上下文恢复。检查点必须独立保存历史内存内容，单纯持有原 mm 的引用不构成快照。

## 功能目标与建议首版范围

1. 平台为 ARM64、OLK-6.6，在 QEMU virt 中验证，使用独立 Kconfig 控制。
2. 支持同一线程组内多个线程的受控用户态测试程序；显式调用新接口创建一个线程组级检查点，不能仅保存调用线程。
3. 保存全部参与线程足够的用户态执行上下文。检查点协调者恢复后以不同返回值标识恢复，其他线程回到各自保存的执行位置；具体接口和协作方式由设计明确。
4. 验证栈、堆、全局可写数据回到检查点内容，支持覆盖这些数据所必需的私有映射；测试程序所需代码和只读映射必须继续有效。最终支持的 VMA 类型及前提在设计中明确。
5. 在信号实际递送时已选择 SIGABRT 默认终止动作、进入 core dump 或退出流程前触发恢复。覆盖 libc abort() 和显式发送 SIGABRT 两种触发方式。
6. 恢复后 TGID 不变，不通过重启整个进程实现恢复；不返回 abort() 调用位置，而返回检查点保存的执行位置。任意当前业务线程（包括检查点后新建的线程）触发 SIGABRT 默认终止动作，均触发整个线程组恢复。采用保留态方案时，原检查点任务及其数字 TID 保持，逻辑退出线程从保留态恢复；不能默认允许陈旧 TID 或不一致的 pthread/futex 身份。
7. 首版采用一次性检查点：一次成功恢复后检查点失效，再次 SIGABRT 按默认语义终止。
8. 对不支持的检查点条件明确返回错误。检查点创建失败不能留下部分有效快照；没有有效检查点时保留默认 SIGABRT 行为。恢复失败不得返回混合的新旧现场，应进入明确定义的失败终止路径。
9. 检查点资源在消费、退出等生命周期结束时正确释放。
10. 创建和恢复都必须协调全部参与线程，形成一致的共享内存及线程执行现场。在任何线程恢复用户态执行前，全部线程必须完成地址空间和执行上下文切换；不能让部分线程继续使用旧 mm 或旧执行现场。
11. 覆盖线程私有栈、TLS、ARM64 基础浮点/SIMD 状态、必要的信号状态；共享地址空间内的数据和线程同步关系必须一致。不得回放检查点之后尚未完成的旧系统调用对恢复地址空间的写入。SVE/SME、阻塞系统调用、futex 等的支持或拒绝策略在设计中明确。
12. 检查点后允许 pthread_create()、线程正常退出、pthread_join() 及 detached 线程退出。允许原任务进入专用保留态，内核资源延迟销毁，但 join 必须能观察退出并返回，栈/TLS 必须能由线程库按通常流程回收或复用。回滚移除检查点后新增的线程，恢复检查点原线程的现场、栈和 TLS。线程变化不使检查点失效，不能以保留固定业务线程集合替代需求。进程整体退出不触发自动复活；leader 逻辑退出且其余线程仍存活时应支持恢复。

## 首版边界

- 支持检查点之后线程集合变化，不支持与线程组外任务共享 mm。建立检查点期间通过协作安全点形成明确线程集合边界；恢复时必须阻止并发创建/退出破坏成员重建，具体同步方法在设计中明确。
- 可要求测试程序配合到达线程组安全点，但检查点后各线程必须能够继续执行并修改状态，不能以“仅一个线程真正继续运行”替代多线程回滚。安全点和恢复时线程停驻协议在设计阶段明确。
- 不恢复外部世界：文件内容、文件偏移、socket 通信、数据库事务等不属于回滚承诺；测试程序在受控资源条件下执行。
- 不支持任意共享可写映射、设备映射、未完成异步 I/O 或任意内核对象快照；具体拒绝条件由设计明确。
- 首版只支持 SIGABRT 默认终止路径；捕获、忽略或阻塞本身不触发强制回滚。abort() 自身可能改变 SIGABRT 的处理和屏蔽状态，以实际递送时的处理动作为准。
- 基线为无 ptrace 调试器的受控测试环境。架构扩展状态、TLS、信号状态和内核登记的用户地址必须在设计中逐项说明恢复或约束方法。
- 权限、接口、快照构造和地址空间切换实现不在需求阶段预先锁定；先验证可行性，再进入编码。

## 验收标准

| 编号 | 场景 | 可观察判定 |
|---|---|---|
| AC-01 | 至少三个线程（主线程及两个工作线程）建立检查点后，各自修改栈、TLS 和共享堆、全局数据，再调用 abort() | 所有线程回到各自保存位置；协调者返回值标识恢复；所有被测数据等于检查点值，TGID 和全部 TID 不变；不是退出重启 |
| AC-02 | 分别由主线程、工作线程调用 abort()，以及显式发送 SIGABRT 触发默认终止路径 | 每个独立测试进程均完成整个线程组的一次回滚；不继续执行异常点后的路径 |
| AC-03 | 已消费检查点后再次 SIGABRT | 父进程 waitpid() 得到 WIFSIGNALED 且 WTERMSIG 为 SIGABRT，不陷入自动回滚循环 |
| AC-04 | 无检查点或功能未启用 | 默认 SIGABRT 终止行为不变；禁用新 Kconfig 的内核可编译 |
| AC-05 | 不受支持的程序条件、非法接口参数或创建失败 | 得到明确错误，原任务仍可正常运行或按原语义终止；无部分有效快照 |
| AC-06 | 重复运行“创建—回滚—退出”和“创建—直接退出” | 无新增内核告警、Oops 或可观察的检查点资源累积；循环次数和资源观察方式由测试设计明确 |
| AC-07 | 编译与运行 | 基于 ~/tools/qemu_arm64_defconfig 构建 ARM64 Image，在 QEMU 执行测试并记录日志；新增代码通过要求的样式检查 |
| AC-08 | 恢复过程中失败 | 整个线程组终止，不继续执行混合现场，不导致内核告警或 Oops；父进程可观察终止结果；SIGKILL 作为失败结果是待确认的设计建议 |
| AC-09 | SIGABRT 被捕获、忽略或阻塞，且未进入默认终止路径 | 不强制回滚，既有信号处理行为保持不变；与 abort() 自行调整信号状态的场景分开测试 |
| AC-10 | 多核下多个线程并发修改状态并触发一次或并发 SIGABRT | 只消费一次检查点，不发生双重恢复、旧 mm 访问或死锁；并发请求如何归并、后续信号如何区分在设计中明确 |
| AC-11 | 检查点后新建线程、检查点原有工作线程退出并被 join 或 detached 回收，再触发 SIGABRT | 检查点仍有效；新增线程被移除，退出的原线程被恢复，最终线程集合及各线程现场匹配检查点；无多余或悬挂线程 |
| AC-12 | 各线程在检查点前后持有不同的 TLS 和基础浮点/SIMD 状态 | 恢复后各线程分别匹配自身检查点值，无线程间串扰；测试不得被编译器优化为空验证 |
| AC-13 | 创建或恢复遇到不能安全停驻的线程/不支持的状态 | 依设计明确拒绝或失败终止；不无限等待，不恢复部分线程，不允许旧内核操作继续写入恢复后的地址空间 |
| AC-14 | 检查点后新建的线程触发 abort() | 该线程不在恢复后线程集合中，整个组恢复到检查点；不返回新线程的 abort() 路径 |
| AC-15 | 线程退出后栈/TLS 内存被回收或复用，再恢复 | 原线程的栈、TLS、线程库身份及同步关系恢复一致；再次 pthread_join()/同步操作不引用错误任务；明确验证 TID 复用或保留策略 |
| AC-16 | leader 通过 pthread_exit 单独退出，其余线程继续运行并触发 SIGABRT | 作为动态线程生命周期的专门用例，目标是恢复检查点中的 leader 及原线程集合、保持 TGID；具体实现及数字身份策略必须在方案阶段证明，不将“整个进程已经退出”与此混淆 |

## 多线程补充语义与调研事项

本节除用户已确认的动态线程生命周期和协作安全点外，信号细节、5 秒协调超时、SIGKILL 失败结果、重复创建错误码等均为待用户在方案阶段确认的设计建议，不是用户新增要求。协调超时应有界进入失败路径，任务实际退出仍可能因不可中断内核等待而延迟。

保留态候选方案保持原任务及其 PID 关联，从而保持原 TID，不能仅 get_pid/get_task_struct 后任由正常退出解除关联。原生内核线程列表和资源计数可在检查点有效期间继续包含逻辑退出任务；这不是用户态业务线程仍然运行，必须明确记录可观察差异及最终释放规则。

- 检查点参与线程是建立时线程组内全部存活线程，保存的内存与全部上下文必须属于同一个一致状态。恢复时协调所有当前线程，包括检查点后新建线程以及逻辑退出的保留任务；不是创建新进程替换整个 A。
- 创建时允许要求全部线程主动进入检查点安全点。SIGABRT 可以在后续运行中触发恢复，不要求故障线程执行用户态恢复代码；若其他线程不能在有界时间内安全停驻，整组失败终止，不声称支持任意内核阻塞状态。首版协调阶段的目标超时为 5 秒，测试验证超时后不继续挂起；不可中断内核等待导致的终止延迟仍受 Linux 原有语义限制。
- 恢复每线程信号屏蔽字及线程组信号处置至检查点值。首版检查点要求无普通 pending 信号；消费触发恢复的 SIGABRT，并归并恢复协调期间已接收的同类触发。恢复协调完成之后递送的新 SIGABRT 遵循恢复后的处置，默认处置下终止。其他非致命异步信号不作为可靠通知回放的支持范围；若在创建/恢复协调阶段出现则中止该操作，避免静默丢弃。SIGKILL 和已经开始的线程组退出优先，不能回滚或吞掉。
- 创建完成、对外发布有效检查点是有效性边界。在此之前收到默认终止的 SIGABRT，按默认语义退出，不使用半成品。有效期间新增或退出线程不使检查点失效。创建和恢复协调阶段的成员变化需序列化或安全处理；无法形成一致状态时创建失败或恢复整组失败终止，不允许部分成功。pthread_create 失败不使已有效检查点失效。
- 恢复失败的可观察结果规定为整组被 SIGKILL 终止；父进程据此区分正常恢复与失败终止。并发的外部 SIGKILL 具有相同结果，不承诺仅凭 wait 状态判断失败来源。
- 一次性指每个检查点最多消费一次；存在有效检查点时重复创建返回 EBUSY；成功消费并完成恢复后允许再次显式创建新检查点，未再次创建时 SIGABRT 正常终止。
- 测试设计须增加：信号屏蔽字/处置恢复、创建和恢复窗口的线程集合变化、并发 SIGABRT 归并、SIGKILL 优先、超时失败、重复创建及消费后重建的验收。并发触发窗口通过测试同步协议确定，不以发送调用发生时刻替代内核实际处理时刻。
