# IOMMU 缺页响应耗时追踪

## 目标

提供单条trace event，直接观察缺页上报到response的时间，支持SMMUv3及其他使用通用IOPF框架的驱动。

## 最终约定

- 事件名：`iommu:iopf_latency`。
- 起点：`iommu_report_device_fault()` 入口。
- 终点：驱动 `page_response()` 回调返回后。
- 成功组装的分组请求以LAST_PAGE fault作为起点并记录其地址；同步错误响应记录被拒绝fault。
- 保留设备、PASID及有效性、group id、地址、response、duration_ns；文本将有效性合并为 `pasid(v)` / `pasid(i)`。
- 不新增CONFIG，不采集或打印 `arm_smmu_cmdq_issue_cmd()` 返回值。
- 不导出 `iopf_latency` tracepoint符号。
- 事件未启用不读时钟；未采到起点不补算；开启/关闭期间的在途请求遵循已有说明。
- 时间戳随iopf_fault传递，iopf_group_alloc显式复制到last_fault，使用kABI预留槽。

## 限制

该区间衡量软件响应处理，包括异步排队及驱动回调；不等同于硬件恢复完成。SMMUv3的RESUME不新增SYNC。

本精简包仅交付当前需求说明；实现以上述约定及patches目录内按编号排序的两份补丁为准。
