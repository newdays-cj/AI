## 社区反馈详情

### 反馈 1：OP_GLOB 拒绝路径缺少 parse_error() 调用

**来源**: Sashiko-bot，经 Steven Rostedt 确认为 "legitimate issue"

**涉及文件**: `kernel/trace/trace_events_filter.c`，`parse_pred()` 函数

**当前代码**:
```c
} else if (field->filter_type == FILTER_WITHIN) {
    unsigned long func;

    if (op == OP_GLOB)
        goto err_free;    // 缺少 parse_error()

    pred->fn_num = FILTER_PRED_FN_WITHIN;
    func = kallsyms_lookup_name(pred->regex->pattern);
    ...
```

**问题描述**: 当用户对 `within` 字段使用 glob 操作符 `~` 时（如 `within ~ "vfs_read"`），代码直接跳转到 `err_free`，但**没有调用 `parse_error()` 设置具体错误信息**。该函数中其他所有错误路径在 `goto err_free` 前均调用了 `parse_error()` 以提供明确的错误提示。唯独此处缺失，导致用户看到泛化的错误消息而非 "Invalid operator"。

**Steven Rostedt 原话**:
> *"This is a legitimate issue. Chen, can you send a v2 and add a proper error message here?"*
（2026-07-07，Message-ID: `<20260707112011.7ca6f721@gandalf.local.home>`）

> *"Hi Chen, do you plan on sending a v2?"*
（2026-07-10，Message-ID: `<20260710141417.1fff0e13@gandalf.local.home>`）

**分析**: 这是一个明确的代码缺陷。`parse_error(pe, FILT_ERR_INVALID_OP, pos + i)` 可以将错误信息设为 "Invalid operator"，与其他同类路径保持一致。Steven 两次催促 v2，此修复应作为 v2 的主要内容。

### 反馈 2：调用栈捕获深度（entries 数组大小）

**来源**: Sashiko-bot，Steven Rostedt 标记为已知限制

**涉及文件**: `kernel/trace/trace_events_filter.c`，`filter_pred_within()` 函数

**当前代码**:
```c
static int filter_pred_within(struct filter_pred *pred, void *event)
{
#ifdef CONFIG_STACKTRACE
    unsigned long entries[16];
    unsigned int nr_entries;
    int i;

    nr_entries = stack_trace_save(entries, ARRAY_SIZE(entries), 0);
    for (i = 0; i < nr_entries; i++)
        if (pred->val <= entries[i] && entries[i] < pred->val2)
            return !pred->not;
```

**Sashiko-bot 的评论**:
> *"Is an array size of 16 entries sufficient here? Since the skipnr parameter is 0, several of these frames will be consumed by internal tracing and filter evaluation functions (such as filter_pred_within() and trace_event_buffer_commit()). This leaves very few slots for the actual call chain, meaning higher-level functions like 'vfs_read' will likely be truncated from the stack trace. Could this cause the filter condition to evaluate to false incorrectly, missing the events we are trying to capture?"*

**历史背景**: 更早的版本中 `entries` 为 32，社区（Steven Rostedt / Masami Hiramatsu）建议缩减到 16，原因是担心内核栈占用过大。`unsigned long entries[16]` 占用 128 字节栈空间。

**Steven Rostedt 的回应**:
> *"This is a current limitation that may be dealt with in the future."*

**分析**: 这是一个**已被讨论并明确权衡过**的设计选择，而非缺陷：
- **栈空间**: 16 个 `unsigned long` = 128 字节，是社区认为安全的上限（从 32 缩减而来）
- **skipnr=0**: 前几帧会被 `filter_pred_within` 和 trace 内部函数消耗，确实减少了实际可用于匹配调用者的槽位
- **Steven 的判断**: 标记为 "current limitation"，可在将来改进，但不阻塞当前补丁合入
- 如果将来需要改善深度，可能的方向：使用 `skipnr` 跳过已知的内部帧（而非增大数组），或在内核栈更大的架构上放宽限制

**结论**: 此问题已被审查者知晓并接受，v2 中**无需修改**。
