# 测试设计 — within 过滤器

## 测试策略

| 类型 | 方式 | 说明 |
|------|------|------|
| 功能测试 | QEMU shell 脚本 | 操作 tracefs 设置 filter，触发事件，检查 trace buffer 输出 |
| 错误路径 | QEMU shell 脚本 | 验证非法输入的错误处理 |
| 编译测试 | Kconfig | 验证 CONFIG_STACKTRACE=n 下编译通过 |

不使用 KUnit（filter 是用户态接口，更适合集成测试）。

## 测试前置条件

- QEMU arm64 环境，内核包含：
  - `CONFIG_TRACING=y`
  - `CONFIG_STACKTRACE=y`
  - `CONFIG_EVENT_TRACING=y`
  - `CONFIG_KMEM_KALLOC_TRACEPOINT=y`（或 `kmem:kmalloc` 可用）
- tracefs 已挂载（`/sys/kernel/tracing`）
- 测试程序：能够触发已知调用路径的用户态程序

## 测试用例

### 用例 1：within == 正向匹配

**目标**：验证 `within == "func"` 在调用栈含目标函数时放行事件。

**步骤**：
1. 清空 trace buffer：`echo > /sys/kernel/tracing/trace`
2. 设置 filter：`echo 'within == "vfs_read"' > /sys/kernel/tracing/events/kmem/kmalloc/filter`
3. 启用事件：`echo 1 > /sys/kernel/tracing/events/kmem/kmalloc/enable`
4. 触发 vfs_read 调用链：`cat /proc/self/maps`（通过 vfs_read 读 /proc，内部触发 kmalloc）
5. 关闭事件：`echo 0 > /sys/kernel/tracing/events/kmem/kmalloc/enable`
6. 检查 trace 中有 kmalloc 事件

**预期结果**：trace buffer 中有 kmalloc 事件（`kmem:kmalloc:` 条目数 > 0）。

---

### 用例 2：within == 负向匹配（不同调用路径）

**目标**：验证 `within == "func"` 在调用栈不含目标函数时阻止事件。

**步骤**：
1. 清空 trace buffer
2. 设置 filter：`echo 'within == "nonexistent_func_12345"' > /sys/kernel/tracing/events/kmem/kmalloc/filter`
3. 启用事件
4. 触发 kmalloc：`cat /proc/self/maps`
5. 关闭事件
6. 检查 trace

**预期结果**：trace buffer 中无 kmalloc 事件（因为不存在 nonexistent_func_12345），但 filter 设置本身不报错（函数存在性延迟校验？）。

> ⚠️ 注意：filter 解析阶段会调用 kallsyms_lookup_name() 校验函数名。不存在的函数名应在 echo 时即报 "No function found" 错误。预期：步骤 2 时 echo 返回错误。

**修正**：预期步骤 2 时返回 `No function found` 错误，filter 设置失败。

---

### 用例 3：within != 操作符

**目标**：验证 `within != "func"` 排除目标调用路径。

**步骤**：
1. 清空 trace buffer
2. 设置 filter：`echo 'within != "vfs_read"' > /sys/kernel/tracing/events/kmem/kmalloc/filter`
3. 启用事件
4. 触发 vfs_read 调用链：`cat /proc/self/maps`
5. 检查 trace

**预期结果**：来自 vfs_read 路径的 kmalloc 事件被排除。trace 中可能仍有其他来源的 kmalloc（系统后台），但 vfs_read 路径产生的不应出现。

> 验证方法：对比 with/without filter 的 kmalloc 数量，filter 后应显著减少（无法完全归零因为系统后台有其他 kmalloc 来源）。

---

### 用例 4：非法操作符（glob）

**目标**：验证 OP_GLOB（`~`）被正确拒绝。

**步骤**：
1. `echo 'within ~ "vfs_read"' > /sys/kernel/tracing/events/kmem/kmalloc/filter`

**预期结果**：echo 返回 `Invalid operator` 错误。

---

### 用例 5：非法操作符（数值比较）

**目标**：验证 `>`、`<` 等被拒绝。

**步骤**：
1. `echo 'within > 123' > /sys/kernel/tracing/events/kmem/kmalloc/filter`

**预期结果**：echo 返回错误（期望字符串但收到数字）。

---

### 用例 6：不存在的函数名

**目标**：验证 kallsyms 查找失败时的错误处理。

**步骤**：
1. `echo 'within == "no_such_function_xyz"' > /sys/kernel/tracing/events/kmem/kmalloc/filter`

**预期结果**：echo 返回 `No function found` 错误。

---

### 用例 7：组合条件

**目标**：验证 within 可与其他条件组合。

**步骤**：
1. 清空 trace buffer
2. 设置 filter：`echo 'within == "vfs_read" && bytes_req >= 1024' > /sys/kernel/tracing/events/kmem/kmalloc/filter`
3. 启用事件
4. 触发 vfs_read 调用链：`cat /proc/self/maps`
5. 检查 trace 中的 kmalloc 事件，确认 `bytes_req` 均 ≥ 1024

**预期结果**：所有记录的 kmalloc 事件 `bytes_req >= 1024`，且来自 vfs_read 调用链。

---

### 用例 8：清除 filter

**目标**：验证 filter 可被清除。

**步骤**：
1. 设置 filter：`echo 'within == "vfs_read"' > /sys/kernel/tracing/events/kmem/kmalloc/filter`
2. 检查 filter 内容：`cat /sys/kernel/tracing/events/kmem/kmalloc/filter` → 应显示 `within == "vfs_read"`
3. 清除：`echo 0 > /sys/kernel/tracing/events/kmem/kmalloc/filter`
4. 检查 filter 内容：`cat /sys/kernel/tracing/events/kmem/kmalloc/filter` → 应显示 `none`

**预期结果**：filter 被清除，事后所有 kmalloc 事件均被记录。

---

### 用例 9：CONFIG_STACKTRACE=n 编译测试

**目标**：验证在不支持 STACKTRACE 的架构上编译通过。

**步骤**：
1. 在不支持 STACKTRACE_SUPPORT 的架构（如 alpha/m68k/nios2）上编译内核
2. 或：手动禁用 CONFIG_STACKTRACE (`scripts/config -d STACKTRACE`)，确保 `CONFIG_TRACING=y`

**预期结果**：编译无错误无警告。`within` 字段不可用（filter 文件中不存在该字段）。

---

## 测试程序

测试脚本 `tests/test_within_filter.sh`，在 QEMU 环境中直接执行。
前置依赖：`/sys/kernel/tracing` 已挂载，`kmem:kmalloc` 事件可用。
