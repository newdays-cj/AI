## 4. Provider 数据和选定内部接口

```c
enum arm64_tlbi_mmio_smmu_mode {
	ARM64_TLBI_MMIO_LEGACY,
	ARM64_TLBI_MMIO_CONDITIONAL,
	ARM64_TLBI_MMIO_REJECT,
};
bool arm64_tlbi_mmio_active(void);
u32 arm64_tlbi_mmio_read_this_cpu(struct mm_struct *mm);
enum arm64_tlbi_mmio_smmu_mode
arm64_tlbi_mmio_smmu_mode(const struct device *dev);
bool arm64_tlbi_mmio_flush_range(struct mm_struct *mm,
                               unsigned long start, unsigned long end);
bool arm64_tlbi_mmio_flush_mm(struct mm_struct *mm);
```

- 通用头前向声明 `struct device` 与 `struct mm_struct`；不用 `<asm/...>`，允许非 arm64 的通用头关闭 stub 编译。当前 SMMUv3 本身依赖 ARM64，不宣称存在合法非 arm64 驱动配置。
- 配置关闭时同名 static inline：active=false、query=LEGACY、read=0；read stub 不是活动路径的错误回退。
- 两个 flush 包装器的关闭配置 stub 返回 false 且无副作用；通用头另前向声明 `struct mm_struct`。
- 配置开启时 active 为全局 static key 查询；SMMU query 及 §4.1 的两个模块桥接包装器导出 `EXPORT_SYMBOL_GPL`，active/read 仅供 built-in TLBI 使用，不给模块额外导出。
- provider 内部状态枚举固定为 `LEGACY / READY / REJECT_LISTED / REJECT_ALL`，不与每设备三态混淆。
- `struct arm64_tlbi_mmio_provider` 含 state、`struct device_node **smmus`、`unsigned int nr_smmus/cpu_capacity`、候选 CPU maps；构建/销毁只访问传入候选，不替换全局 provider。
- `struct arm64_tlbi_mmio_cpu_map` 含 `struct resource res`、`void __iomem *base`、`bool claimed`；按候选 `cpu_capacity` 分配并先校验 id 小于该上界，再访问数组。生产 P1 将上界初始化为 `nr_cpu_ids`，仅 possible 项使用；隔离 fixture 可用独立上界 8 测试 {0,2,7}，不要求宿主具有 8 个 CPU。
- 成功后发布 `DEFINE_PER_CPU(void __iomem *, arm64_tlbi_mmio_base)`；资源/映射及 scope 节点引用永久保留。
- 临时 CPU 表与 claim scope 分开管理：资源失败释放 CPU 表，仍保留可解析 scope 作为拒绝依据。
- 不以订阅者存在与否决定读取；active 的 eligible 操作即使 `mm_has_notifiers(mm)==false` 也必须消费自己的状态。

### 4.1 下游旁路的模块安全桥接

`arm64_tlbi_mmio_flush_range` 和 `arm64_tlbi_mmio_flush_mm` 均在 built-in provider 源文件定义并 `EXPORT_SYMBOL_GPL`。
内部通过 T11 `arm64_tlbi_op_active(mm)` 查 active（生产仍调 P6），false 时不发 TLBI/DSB、不读、不通知；true 时分别调用规范 `__flush_tlb_range(TLB_FLUSH_VMA(mm,0),...,PAGE_SIZE,false,0)` 或 `flush_tlb_mm(mm)`，返回 true。
range 包装器用局部 VMA 对象传地址，合法半开用户范围按规范 helper 归一化和超限回退；整 mm 必须调用独立 mm 包装器，不把 `ULONG_MAX` 当作普通 range 末端参与 round_up。
桥接本身不增加读取、DSB 或 notifier，不回调到 zcopy/OBMM，不形成递归。`arm64_tlbi_mmio_active()` 无需另导出给这些模块。

zcopy/OBMM 对应函数入口各执行 `if (arm64_tlbi_mmio_flush_range(...)) return;` / `if (arm64_tlbi_mmio_flush_mm(mm)) return;`。
false 时原算法逐句保留，zcopy 原 kallsyms 初始化不动；不导出通用旧 raw dispatcher、不新增动态符号查找。
OBMM active 会增加原来没有的通知，这是用户态失效纳入新功能的有意行为，不声称其 active 行为与旧版完全相同；须审计调用方锁序。

## 5. DT 软件草案与初始化事务

这是软件提出的 ABI，不是用户提供的硬件布局事实；尤其 `smmus` 用于隔离未选择的 SMMU，并不证明硬件覆盖。

```dts
/* 仅布局示意；宏为元变量，不是可编译板级 DT；父总线 cell 数亦须适配。 */
tlbi-status@CPU0_STATUS_ADDR {
	compatible = "VENDOR,arm64-cpu-tlbi-status-v1";
	reg = <CPU0_STATUS_ADDR 4>, <CPU1_STATUS_ADDR 4>;
	cpus = <&cpu0 &cpu1>;
	smmus = <&smmu0 &smmu1>;
	status = "okay";
};
```

`VENDOR` 只是 METAvariable；不得作为字符串字面量进入真实 DTS、match table 或 schema。V 门禁要求真实已注册厂商前缀及 compatible。

1. 仅允许一个 enabled 匹配节点；无 enabled 节点为 LEGACY；多个 enabled provider 直接 REJECT_ALL。
2. **先解析 claim，独立于 reg 校验**：`smmus` 必填非空、plain phandle 列表、唯一、均可解析为 SMMUv3 节点。
3. 缺失、格式错误、重复或无法定位 scope 的 `smmus` 属不可界定 claim，REJECT_ALL；不得按“平台不支持”静默降级。
4. claim 有效后验证 `cpus` 为 plain CPU phandle 列表；`cpus[i]` 与 `reg[i]` 严格配对，数量等于 possible CPU 数。
5. 用 `of_cpu_node_to_id()` 求逻辑 id；拒绝缺失、重复、不可解析、非 possible CPU，禁止把数组下标当 Linux CPU id。
6. 每个 reg 翻译后必须恰为 4 字节、4 字节对齐、物理区间无溢出且相互不重叠；数量不得多/少。
7. 全部验证后依次 `request_mem_region`、`ioremap`；占用冲突/映射失败均回滚，不发布部分 CPU base。
8. claim 有效但 cpus/reg/分配/映射失败为 REJECT_LISTED；若连 scope 保留都失败则 REJECT_ALL。
9. 成功映射不做初读、不做清零；确认 H1–H4/V/C 的平台契约后才允许发布 READY 和 `static_branch_enable`。
10. 门禁是代码合入及平台接入前的技术签核，不新造 DT 的“已批准”布尔属性来代替证明；门禁未满足不提供可激活生产实现。

| Provider/设备条件 | query 结果 | 效果 |
|---|---|---|
| 配置关闭、无 enabled 节点 | LEGACY | 所有 SMMU 旧路径；无 MMIO |
| READY 且设备 OF 节点在 smmus 内 | CONDITIONAL | new=TLB-only，old=ATC-only；仅 new 受 bit0 门控 |
| READY 且未列出（含 ACPI 设备） | LEGACY | 此 SMMU SVA 保持旧槽 |
| REJECT_LISTED 且在 scope 内 | REJECT | 仅拒绝其 SVA domain allocation |
| REJECT_LISTED 且未列出 | LEGACY | 无关 SMMU 不受影响 |
| REJECT_ALL | REJECT | 所有 SMMUv3 SVA allocation 拒绝，包括无 OF 节点设备 |

`arch_initcall(arm64_tlbi_mmio_init)` 早于 built-in SMMUv3 的 device-init 注册；模块加载同样只查询已定型状态。
此前 TLBI 仍走 legacy，尚无 active consumer；固件必须保证首次 activation 无旧状态，软件禁止额外 drain。
CPU 表覆盖 possible CPU（含离线 CPU）；online/offline 不重新映射/读清，挂起恢复不重新试读，无 unload/运行时切换。
初始化失败清理仅 `iounmap/release_mem_region/of_node_put/kfree`；保留拒绝分类所需 scope；所有清理都不能读寄存器。

## 6. TLBI 完成与通知时序

逻辑操作定义为 `flush_tlb_mm`、`__flush_tlb_page_nosync`、非 fallback 的 `__flush_tlb_range_nosync` 一次调用。
每个操作包含全部 KPTI 配对、repeat workaround 和 range 拆分；内部 DSB 不是额外读点。

```text
active?
  否：执行现有指令、DSB 和旧通知时序，不读状态，不调用新链
  是：preempt_disable(); local_irq_save(flags);  // 在首条 TLBI 前
      dsb(ishst); 发出此逻辑操作的全部 TLBI; dsb(ish);
      status = arm64_tlbi_mmio_read_this_cpu(mm);  // 唯一 readl(base + 0)，保存 u32
      local_irq_restore(flags); preempt_enable();
      mmu_notifier_arch_invalidate_secondary_tlbs_post_tlbi(
          mm, start, end, !!(status & BIT(0)));
      // 单 SRCU、单遍：每项先条件 TLB，正常返回后再无条件进入其 old。
```

- `readl` 是小端 32 位偏移 0 的软件草案，与 4 字节 reg 配套；不使用 relaxed read、轮询或二次确认。
- 读取整个寄存器并清除所有位，保存局部 `u32` 后恢复调用者原 IRQ/preempt 状态，再进入 post dispatcher；不是两条链或两次遍历。
- 原本 IRQ/preempt 禁止的调用者仍保持原状态；不承诺回调时 IRQ 必然开启，只保证不额外扩大本功能保护区间。
- IRQ 恢复后即使发生嵌套 TLBI，外层使用已保存值；NMI/SError/更高 EL 的区间内干扰不能靠本地 IRQ 屏蔽解决。
- 其他旧订阅者不依赖 bit0；listed SMMU 的 ATC 也不依赖 bit0。禁止先跑所有 old 再跑 new；只承诺同一订阅者 new→old，不承诺所有设备 TLB 都先于所有设备 ATC。无订阅者仍先读。
- mm 通知 `(mm, 0, ULONG_MAX)`；page 为页对齐 `[uaddr & PAGE_MASK, +PAGE_SIZE)`；range 为原代码归一化区间。
- range 先 round_down/up、算 pages、检查 limit；超限只委托 `flush_tlb_mm`，不再另行 issue/DSB/read/通知。
- `flush_tlb_page`、`__flush_tlb_range` active 时省略尾 DSB，不新增读取；inactive 时保留原尾 DSB。
- active 的 `arch_tlbbatch_should_defer` 固定 false；inactive 保留 repeat workaround 判断，无单 mm 批次元数据。
- young 与 contpte 自然经 nosync 核心覆盖，active 失去原延迟完成优化；young=false 不发 TLBI、不读。
- `tlb_flush` fullmm 且无实际 TLBI 分支不读；需要整 mm 失效则由 mm 核心读一次。
- kernel/global/Stage-2 不加读取，但它们是否污染本状态是 H2 门禁，不能以“不接入”当作硬件隔离证明。

**C 兼容性门禁**：active page/range 的旧回调从 pre-DSB 改为 post-DSB，属于有意加强，不声称精确时序不变。
必须审计所有 arm64 可达旧消费者（含未列入 scope 的 SMMU、`logic_ummu` 和间接 helper），逐个记录可达配置、锁/完成依赖。
已按 Kconfig 核查四个旧槽注册者：SMMUv3（ARM64）及 Logic UMMU（ARM64 && ARCH_HISI）可达；Intel SVM 受 X86_64 限制，OCXL 受 PowerNV 依赖限制。两项 ARM64 回调未见显式 pre-DSB 依赖，这只是有界源码结论，不是硬件签核。

## 7. Notifier 与 SMMUv3 接入契约

选定的内部 API（old/new 的四参数回调类型完全相同）：

```c
void (*arch_invalidate_secondary_tlbs_conditional)(struct mmu_notifier *subscription,
	struct mm_struct *mm, unsigned long start, unsigned long end);
static inline void mmu_notifier_arch_invalidate_secondary_tlbs_post_tlbi(
	struct mm_struct *mm, unsigned long start, unsigned long end, bool need_tlb);
void __mmu_notifier_arch_invalidate_secondary_tlbs_post_tlbi(
	struct mm_struct *mm, unsigned long start, unsigned long end, bool need_tlb);
```

- 公共 inline 仿现有 wrapper：`mm_has_notifiers(mm)` 后调用 core；`CONFIG_MMU_NOTIFIER=n` 同签名 no-op。两者没有生产模块导出；N3 如由独立 KUnit 模块直接测试，只使用 `EXPORT_SYMBOL_IF_KUNIT` 测试命名空间可见性。bool 只供架构→core，消费者从不接收 bool/原始状态。
- core 在现有 `srcu` 中**一次 read_lock、一次 hlist 遍历、一次 unlock**。每项执行 `if (need_tlb && ops->new) new(mn,mm,start,end); if (ops->old) old(mn,mm,start,end);`，new 绝不在 false 时调用。
- old-only 每次一次、与 bit0 无关；new-only 合法；两槽为空无操作；old+new 合法，不比较函数指针、不校验 SMMU 特定职责。注册仅拒绝 `subscription && ((old || new) && (invalidate_range_start || invalidate_range_end))`，返回 `-EINVAL`；NULL itree 不变。
- 单 SRCU 保护配对调用期间的对象/ops 生存期，free 等待读者退出；**不保证与 release 原子互斥**。按 `mmu_notifier.c:812-850`，unregister/release 可以并发开始/运行，然后删链并等待；不声称注销不能开始。
- 不改 release/unregister/put/free、ASID reuse 并发、domain free 或模块 synchronize；无第二张订阅链、无全局旧链开关。
- legacy 表 `arm_smmu_mmu_notifier_ops`：old=现有合并回调、new=NULL。conditional 表 `arm_smmu_mmu_notifier_conditional_ops`：new=`arm_smmu_mm_invalidate_tlb`、old=`arm_smmu_mm_invalidate_atc`。
- 两表的 `.release=arm_smmu_mm_release`、`.free_notifier=arm_smmu_mmu_notifier_free` 完全相同，函数体不改；release 的整 ASID/full ATC 不受 bit0 门控。
- S3 纯 size helper 被 S4 TLB-only、S5 ATC-only 各自调用；允许重复同一归一化算术。S6 现有合并回调改为 S4→S5，保留外部语义，不声称函数体逐字不变。
- S7 typed ops selector 对 LEGACY/CONDITIONAL 返回相应 `const struct mmu_notifier_ops *`，REJECT 返回 NULL；S8 mode helper 先检查 NULL，再进行原 domain/ASID/notifier 分配。
- 实际 S1 取得 `smmu` 后，**一次**查询 `arm64_tlbi_mmio_smmu_mode(smmu->dev)`，再调用 S8；REJECT 在 alloc/xarray/register 前返回 `ERR_PTR(-EINVAL)`。不改 probe、非 SVA domain 或其他 SMMU 驱动。

**错误策略**：legacy 保留原 void callback，active 拆分仍须保留既有错误策略；不把“返回”升级为硬件故障时必然成功的证明。
正常路径 CMD_SYNC 等待同步完成；ASID 忽略 issue 返回，range 忽略部分 batch submit 返回，callback 忽略 ATC 返回；队列满可能持续重试。
不新增 panic、额外重试、fallback 刷新或返回错误的 notifier；严格 fail-closed 需要另行修改全驱动契约并回到需求审核。

### 7.1 ATC 处理与 bit0 边界

**源码现状与保留语义**（§2 新增锚点均已回读）：

1. `arm_smmu_mm_arch_invalidate_secondary_tlbs`（`sva.c:132-162`）先算 `size = end - start`。无 `RANGE_INV` 且 `size >= CMDQ_MAX_TLBI_OPS * PAGE_SIZE` 时归零；有 `RANGE_INV` 且 `size == ULONG_MAX` 时归零。零值触发整 ASID，否则调用 range ASID 失效（入口见主文件 `2518-2532`），随后将**同一归一化 size** 传给 `arm_smmu_atc_inv_domain`。因此大范围 TLB 回退也会令 ATC full invalidate；拆分后仍须保留这种全失效/过度失效语义，除非另行专项审核，不能默默改回原始 range。
2. `arm_smmu_atc_inv_domain`（主文件 `2321-2383`）不支持 `ARM_SMMU_FEAT_ATS` 时直接返回 0；支持时先执行 `smp_mb()`，**再**读 `nr_ats_masters`，无活动 ATS master 则返回 0。屏障保证先前 main TLB 失效完成与并发 `arm_smmu_enable_ats()` 的计数发布/ATS 启用之间的排序，必须保留，不能因 bit0=0 或拆分回调而移除。
3. 通过上述检查后初始化 batch，先 `arm_smmu_preempt_disable`，再 `spin_lock_irqsave(&devices_lock, flags)` 遍历 domain 的 masters；跳过 `!master->ats_enabled`。`nested_ats_flush` 使用 `IOMMU_NO_PASID, 0, 0` 全 ATC 失效，否则用 `master_domain->ssid` 和正常 `iova/size`。每个 stream 分别填写 `cmd.atc.sid` 并加入 batch；先释放锁、恢复 IRQ，再最终提交 batch，最后 `arm_smmu_preempt_enable` 恢复配对状态。不得颠倒该锁、抢占与最终提交边界。
4. `arm_smmu_atc_inv_to_cmd`（`2234-2298`）固定采用 **4KB** 粒度，与内核 `PAGE_SIZE` 无关；`size=0` 编码 `ATC_INV_SIZE_ALL`，否则选覆盖范围的最小、按跨度对齐的 2 次幂区间，有意允许过度失效。`substream_valid` 当且仅当 `ssid != IOMMU_NO_PASID`；源码注释明确，无 PASID 失效可连带范围内 PASID-tagged 条目，不能称为“仅清无 PASID 条目”。
5. batch submit（`1180-1184`）以 `sync=true` 提交，正常路径等待 CMD_SYNC；`1090-1113` 显示超时会记录限频错误并返回错误。ATC helper 返回提交结果，但外层 void SVA 回调忽略它；“同步调用返回”不是所有故障下硬件必已完成的证明。本次不增加 panic、重试或新错误策略。

**本轮必须遵守的边界**：READY 且列入 scope 时，bit0=0 仅免除软件 SMMU TLB；ATC 处理仍须进入独立判断。只有 ATS 支持、存在活动 ATS master 且具体 master 启用 ATS 时才有对应 ATC 命令，故“不受 bit0 门控”不等于“无条件发 ATC 命令”。bit0=1 必须先软件 SMMU TLB 失效并在正常路径完成，再处理 ATC；bit0=0 仍保留 CPU TLBI/DSB 完成及上述屏障。inactive/legacy 合并回调的外部语义、`arm_smmu_mm_release`（`sva.c:164-194`）的整 ASID/full ATC 路径均不改变，也不受 bit0 门控。

**本轮采用 §7 Option A**：同一订阅者条件 TLB 正常完成→ATC-only；不采用无条件的单消费者状态回调。软件边界已定，硬件/时序门禁仍独立阻塞。

**后续六项测试义务（未执行、非覆盖声明）**：

1. READY/bit0=0、ATS 活跃且 master 启用：软件 SMMU TLB 次数为 0，仍有对应 ATC 失效。
2. READY/bit0=1：软件 SMMU TLB 与 ATC 均发生，验证 TLB 正常完成先于 ATC，无重复 TLB。
3. ATS 不支持或无活动 ATS master：无 ATC 命令；核实支持 ATS 时屏障仍在计数检查前。
4. 混合 master：禁用 ATS 的跳过；nested 全失效/无 PASID、普通 full/range、PASID 有效位及逐 stream SID 均保留。
5. 大范围无 RANGE_INV 的归零/full ATC，以及 RANGE_INV 下 `ULONG_MAX` 的 full ATC、4KB 幂次覆盖语义均保留。
6. 超时/错误传播边界、锁/IRQ/抢占配对、SRCU 注销及 release/free 生命周期与 legacy 一致，不新增错误策略。

### 8.2 G1：持久候选构建与资源失败

P1 和测试 K9 调**同一个非 __init P11**；P11 调实际 P2/P3 解析、验证、申请/映射及 P4/P5 清理。P12 同样持久存在，测试绝不调用 init wrapper、publish 或已释放 init text。
P1 在 build 前写入实际 `nr_cpu_ids` 上界；K8 写入 fixture 独立上界。K23 按该上界分配，P3 在任何下标访问前检查 id，不能让稀疏假 CPU 7 越过 4 CPU QEMU 的实际数组。
P11 返回 0 表示分类完成（含 LEGACY/REJECT_LISTED/REJECT_ALL），state 是分类依据；输入候选所有权字段初始化为零，cpu_capacity 已由调用者设置，build 不清除该上界；READY 候选仍不激活。P1 只编排 build/所有权转移/发布/destroy：将应永久保留的 scope/maps 转入全局 provider，并清空候选相应所有权字段，再调用同一 P12 清临时余项；失败分类也保留必要拒绝 scope。仅 P1 在 READY 时发布 per-CPU base/启用 key，无另一个生产 publish helper；P8 使用不可变全局，P13 使用显式候选。
fixture 持有自己的 provider、OF tokens、CPU 集合与设备，绝不设置“全局 provider override”。K15–K31 是有限、typed leaf；真实生产路径分别调用 OF/分配/request/map 原语，无通用 ops 表。
K5/K8/K10/K12 预分配 ledger，使用公开 `kunit_activate_static_stub(test, fn, replacement)`（宏检查替身类型）；其返回 void **不证明安装成功**。保留 `kunit_hooks.get_static_stub_address` 作为 **TREE-PINNED INTERNAL（绑定当前源码树的内部依赖）**，不是公开 API：先检查 hook 函数指针非 NULL，每次 activation 返回后再确认 hook 非 NULL，并以精确 real fn 地址查询，结果必须等于预期 typed replacement 地址；只有通过核验的目标才进入 active ledger。行为探针不能证明精确目标，不可替代此核验。
首次 activation 前 fixture 已由 test->priv 可达；每轮安装/模式重配先置 run_enabled=false，当前模式全部必需目标核验齐全才置 true。hook 缺失、lookup 为 NULL 或地址不匹配，installer 返回 -EINVAL，保持禁跑；所有 runner（含 CHECK_ONLY）在任何真实入口/raw/OF/MMIO/CMDQ 前拒绝，缺失/停用 ledger 同样拒绝。失败回收只 deactivate ledger 已确认且仍 active 的目标，**绝不 deactivate 本次核验失败目标**；ctx 分配 fatal assertion 的部分安装由 K14 per-case .exit 处理。K8 核验 K15–K31 全部目标后才允许 K9。fault 完整取值为 NONE/SCOPE_ALLOC/MAPS_ALLOC/REQUEST_N/MAP_N/SVA_ALLOC/ASID_ALLOC/NOTIFIER_REGISTER；fixture 保存第 n 次索引，不适用当前 installer 的取值返回 -EINVAL。OF 非法输入由 fixture 数据表达。
**E_KUNIT_OOM（不注入）**：当前 `lib/kunit/static_stub.c:113-120` 先分配 framework-owned 私有 ctx（失败会 fatal），再调用 kunit_alloc_resource；后者失败未检查，可静默返回并泄漏前述 ctx。调用者没有该私有 ctx 的可释放指针，不能伪造释放；精确 lookup 失败必须 fail-closed、零 raw/真实 I/O。特性自有 ledger/资源在有效所有权范围内仍须平衡，但不宣称框架或全局分配平衡。该已知框架泄漏保留例外，本轮不注入 KUnit OOM、不修 KUnit core。
此内部 hook 是满足精确目标证明的最小依赖。移植/升级前必须重新核验当前树的 hook 可见性/lookup 语义、activation 资源分配/错误行为，以及 `lib/kunit/test.c:444-450,476-484` 的 per-case .exit 次序与 cleanup kthread current-test 设置；不得把当前依赖当稳定公开契约。
K15–K21 统一引用记账；K22–K29 用预分配 token，零真实资源 I/O。依次覆盖 §5 十项、稀疏 CPU、各失败位置、重复 cleanup、保留拒绝 scope 和最终销毁；所有失败路径零 MMIO 读取/零 publish。

### 8.3 G2：真实 inline 控制流与 raw 指令隔离

K5/K7 位于 provider 的同一翻译单元，包含真实 `tlbflush.h`；T7–T13 的 static inline 定义、stub 安装取址和 bridge 调用都在该 TU，禁止测试 `.ko` 自己展开另一份 inline 再安装不相同地址的 stub。
`request` 固定含 op（MM/PAGE_NOSYNC/PAGE/RANGE_NOSYNC/RANGE/DEFER/BRIDGE_MM/BRIDGE_RANGE/CHECK_ONLY）、mm/start/end/stride/last_level/tlb_level。K7 调真实入口或仅做 CHECK_ONLY 校验，无复制版 TLBI 算法；K5 在进保护区前完成替身安装和逐目标精确地址核验，run_enabled 与 verified ledger 均满足才准入。
T7/T8/T9 从原逻辑提取最小 raw issue 块（含 dsb(ishst)），**整体 stub**，避免 ASID 访问与破坏性 TLBI；T10 stub 最终 DSB。归一化/阈值/fallback、active 分支、单次 P7 read、保存值/恢复/新 dispatcher 仍执行同一生产控制流。
T11 以目标 mm 注入 active=true，而不是打开全局 key；T12/T13 只控制上限/defer 判断。P7 增 mm 用于隔离，不以 mm 选择实际 per-CPU 寄存器。
每处 redirect 前必须满足 `in_task() && kunit_get_current_test()==ctx->test`，并且 supplied mm==ctx->target_mm；provider leaf 另要求 p/np/res/token 属该 fixture，SVA leaf 要求 dev/domain/smmu 在其所有权集合。
不得只用 kunit_get_current_test：IRQ 中断测试任务时可看见同一 current 指针。守卫失败时真实生产调用按原路径执行，**bridge** 若上下文或 stub 不全则先拒绝，不允许测试请求误走硬件。
T7–T9 的错 mm/test/IRQ 守卫 fallthrough 仅做源码/构建核查，绝不直接运行负向探测；K7 在 raw 入口前拒绝这些请求。其他 guard 运行时负例仅限 K2 no-op、bridge 拒绝等确实无破坏性的路径；禁止让假 mm/OF/resource/device 对象进入真实硬件、OF 或资源调用。
不改全局 static key、per-CPU bases 或 CPU capabilities；explicit candidate/context 是隔离边界。IRQ-off 内只做预安装 stub lookup/记录，不分配、不安装、不 assert/打印；KUnit resource lookup 的 spin_lock_irqsave/refcount 可用。
**E_RAW（显式运行时覆盖例外）**：raw KPTI 配对、repeat 指令、TTL 编码、range scale/num/奇数尾分解分支在这些用例中**没有执行**；range-cap 注入不等于覆盖 raw 循环。以源码/反汇编核查并在硬件资格测试补齐，不复制算法、不宣称 100% runtime。
**E_KEY**：fixture true 只验证 T11 以上分支，不证明 P6 全局 static-key true 指令已运行；其真分支依赖独立构建/反汇编及门禁通过后的硬件激活证据。
**E_BYPASS_RAW**：K46/K47 只测 active 的真实 Z1/O1→P9/P10→规范事务，并要求 active/stub 配置在 run 中不可变。inactive 的原复制 raw 算法不在假 mm 上运行；其语义以源码/反汇编及受控真机回归核对，不能用包装器 false 替身的测试冒充已执行 legacy raw。
**E_IO / E_ENTRY**：typed leaf 替身让真实校验、回滚和 ATC 编码控制流运行，但被替换的真实 OF/分配/物理映射/设备命令转发路径不因此取得运行证据。K11 直接运行 S8，不覆盖 S1 外层一次 mode 查询的实际入口；后者以源码/构建核对并保留后续平台运行义务。P3/P4/P12 的 CPU 遍历使用候选上界及 possible leaf，不能绕回宿主全局 possible mask 来遍历假 CPU。
**E_CALLER**：直接 T2/T3/T6 用例不执行其他 TU 中的实际调用方。`pgtable.h` young、`contpte.c`、`tlb.h` fullmm gather（无 TLBI/实际 mm）和 `rmap.c`/`tlbbatch.h` reclaim add_pending/batch flush 的接入、条件、对齐与完成点须分别源码/构建核查，并保留合格平台运行义务；不新增 bridge，不以 provider TU 的 inline 展开或事件代替这些调用方的运行覆盖。
T14 为共享 limit helper 加 mm 后，用户调用点传目标 mm；`flush_tlb_kernel_range` 仅机械传 NULL，守卫不匹配 fixture，仍使用原能力判断且绝不读取状态。zcopy legacy 调用点同步加 mm 参数，不改变原算法；此签名传播也须在构建/审计清单中核对，不能漏掉 kernel-range 调用点。

### 8.4 G3：SVA 分配、split callbacks 与真实 ATC 编码

S3–S8 由独立 `.ko` 经 KUnit 命名空间直接调用；S7 就是 typed get-ops 入口，不再增加另一个未列名 getops 包装器。S3/S4/S5/S6 同一 fake domain 检查归一化一致及 legacy TLB→ATC。
S1 查询一次后进入 S8；S8 通过 K37 获取 fake/real smmu，以 S7 选表，REJECT/NULL 先返回，再走 K32–K36 的原分配/ASID/注册/错误回滚。只包装这些 S8 leaf，不替换生产 xarray，也不修改 release/free/domain_free。
K10 的 fault 固定 NONE/SVA_ALLOC/ASID_ALLOC/NOTIFIER_REGISTER，分别注入 ERR_PTR(-ENOMEM)/-ENOMEM/-EINVAL；K11 执行真实 S8。检查拒绝零操作、三失败逆序回滚、两模式正确表及成功对象内容；fake 成功对象由 fixture ledger 清理，不把假注册对象交给真实 notifier_put。
callback 子用例用 K38–K40 捕获直接 helper 调用；返回时记录 TLB_DONE/ATC_DONE，只证明 mock 返回先后。真实 ATC 子用例经 K12 停用 K40 替身，调用真实 K40/K41，K42/K43/K44 全部预装后才能运行。
K44 避免真实 CMDQ 获取；K42 整函数替换只捕获每次调用的 smmu/batch/cmd 参数，不执行真实 batch_add 内部满批/forced-sync/提交分支，也不模拟其覆盖。上述内部控制流归 E_IO 源码/构建审计及合格平台回归；K43 仅模拟最终返回。fake smmu/domain/master 的锁、devices 链表、计数、streams/SSID 全部初始化，保留真实 ATS 判断/smp_mb/遍历/嵌套/锁与抢占配对。
测试 ATS 不支持、支持但计数零、混合 master、nested 全失效、逐 SID、PASID/无 PASID、full/range/大范围归零以及错误返回被原 void callback 忽略。smp_mb 的存在/位置由源码与反汇编核查；并发硬件排序及 CMD_SYNC 真正完成不是 RAM/mock 证明。
K38–K44 的 guarded redirect 仅识别当前 fixture 的显式对象；K41 是纯编码器不需 redirect。不会将真实设备命令送入 fake 队列，也不为生产添加更宽 ops 框架。

### 8.5 G4：有界事件记录、注销与销毁

`fixture` 预分配 **256 条**记录及 overflow flag；记录含 enum event、mm/start/end/value、CPU、IRQ 状态、preempt count、初始 IRQ/preempt 状态。事件枚举固定 ISSUE_MM/ISSUE_PAGE/ISSUE_RANGE/FINAL_DSB/READ/RESTORE/OLD_ENTER/COND_ENTER/TLB_DONE/ATC_ENTER/ATC_SUBMIT/ATC_DONE。
IRQ/preempt/CPU 快照在记录锁改变 IRQ 状态前取得，CPU 用 raw_smp_processor_id 采样；初始状态在 pin/save 前保存。只要求 ISSUE 至 READ 同 CPU，RESTORE 后允许迁移，不错误扩大 pin 区间。
K2 在真实保护恢复后标 RESTORE；raw 替身记录 ISSUE，K1 记录 READ，K3/K4 记录 ENTER，SVA helper 替身及 ATC batch 捕获记录 DONE/SUBMIT。没有 ATC 命令时只可出现 ATC_ENTER/ATC_DONE，不能虚构 ATC_SUBMIT。
记录/查找只用预分配存储与 spin_lock_irqsave；overflow 仅置位，恢复原状态后统一 assert。对每个 bit0/高位组合验证 ISSUE→FINAL_DSB→READ→RESTORE→每项 COND_ENTER/TLB_DONE→OLD_ENTER/ATC_ENTER；false 无 COND，old-only 不过滤。
测试初始 IRQ enabled/disabled 与 preempt enabled/disabled，回调必须看到调用者原状态而非一律 IRQ-on；嵌套事件使用各自保存值。无 notifier 也必须 READ，fullmm 无实际 TLBI 则不读。
注销并发测试由 K13 的显式 data/completion 协调，订阅者用 K3/K4/K45 自己的 container/计数 callback，不用 current-test 硬件替身，也不阻塞/睡眠于 notifier callback。短暂原子计数握手需独立 CPU、超时与恢复后断言；验证注销等待在途调用结束，但允许 release 先开始。
fixture 生命周期统一由 `struct kunit_suite.exit = tlbi_test_fixture_exit`（K14，`void (struct kunit *test)`）这个 **per-case .exit** 执行，不是 suite_exit。`lib/kunit/test.c:444-450` 保证它早于通用资源清理，`476-484` 的 cleanup kthread 设置 current->kunit_test=test，且处于 in_task，故既有 current-test/对象 guard 在清理时仍有效；禁跑标志只阻止 runner，不撤掉受保护析构所需 redirect。activation 资源自动清理为 LIFO，不能把受 stub 保护的析构寄托在自动清理上。fixture 用普通分配，由 K14 唯一拥有/释放，不注册另一个会释放它的 resource；分配成功即写 test->priv，先初始化所有权/进度字段，再进行任何可能 fatal 的 activation。
正常、核验不匹配及 fatal/部分安装退出均为：run_enabled=false、停止并等待 worker → 所需 verified stub 仍 active 时销毁已创建候选/假对象并清空其所有权字段、核对特性自有余额 → K6 仅对 ledger 确认且 active 的目标显式 kunit_deactivate_static_stub 并标 inactive，绝不停用核验失败目标 → 注销真实计数订阅者、等 SRCU/异步 free 同步 → 释放存活 mm、缓冲及 fixture，清空 test->priv。K14 对 NULL/部分 fixture/重复调用安全，清理路径不用会提前中断剩余收尾的 fatal 断言；对象仅在其所需 stub 全部核验后创建，部分安装不触发未受保护析构。自动 activation resource cleanup 仅为残余已注册安装安全网，无法回收 E_KUNIT_OOM 未注册的私有 ctx；其他自动资源只可持有独立惰性存储，不能拥有 fixture 或承担 stub 消失后的受保护析构，避免双重释放。不宣称 E_KUNIT_OOM 下框架/全局无泄漏。
bridge 在 stub 关闭或不齐时只返回错误，不能做硬件 walk；销毁 provider token 必须在其 leaf stub 尚在时完成。已停用 stub 的 notifier release 仅用自有计数，不碰假 SMMU/硬件。
**G5 保留窄例外**：N4 原 kzalloc/mm_take_all_locks 失败仍按源码检查/可安全验证的既有机制记录，禁止全局 allocator/锁故障注入来硬凑 runtime 全分支。新注册组合分支必须真实执行，不由 G5 豁免。
非法注册的 9 个组合向量均独立断言 `-EINVAL`；共用校验点的 `WARN_ON_ONCE` 每个专用启动最多出现一次，不重置全局 WARN 状态，也不要求每向量新告警。白名单仅允许该注册校验点、该叶子 TC 执行窗口内的预期 WARN（精确符号/源码位置及匹配构建）；重复或其他 WARN 均失败，返回值断言不依赖告警出现。
