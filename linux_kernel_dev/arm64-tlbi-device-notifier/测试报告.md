# 隔离软件原型测试报告

## 范围

用户明确授权先做隔离软件原型。测试对象为真实 notifier 软件入口、注册规则和 SMMUv3 纯范围归一化；生产仍走 legacy SVA ops。本报告不是硬件资格、完整 88-ID 实现或 gcov 覆盖率报告。

- 基线 HEAD：`aba0b453d75e1c80f97cb5faf5718925b6844997`，叠加 `prototype.patch`。
- 共享源码存在已有 in-tree 生成文件，使用 `source-prototype/` 干净归档快照构建，未清理共享目录。
- Linux 6.6.0，aarch64-linux-gnu-gcc 13.3.0；完整 `~/tools/qemu_arm64_defconfig` 基线加 KUNIT=y、MODULES=y、ARM_SMMU_V3=y、ARM_SMMU_V3_SVA=y。实际配置见 `build-prototype/.config`。

- 原 Buildroot rootfs.cpio 加临时 initramfs，未写原 rootfs。运行命令：`bash tests/run_qemu.sh`。

## 手动运行证据

主会话实际运行 runner，退出 0。串口原始日志：`qemu-prototype.log`；宿主输出：`qemu-prototype-host.log`。

| 场景 | 预期 | 观察结果 | 证据 |
|---|---|---|---|
| 空订阅、四槽组合 × need false/true | 只在 true 调新槽，old 始终按订阅调用，参数一致 | 每轮 notifier 11 个结果通过，含 8 个参数化向量；零 fail/skip | 串口 `dispatch_empty`、`dispatch_slots` 和 suite totals |
| 混合订阅、同订阅 new→old、注销后再次分发 | 不过滤其他 old；注销后零新调用 | `dispatch_mixed_then_unregister` 两轮通过 | 同一串口 case 结果 |
| 注册组合 | 16 组合中 7 合法、9 返回 -EINVAL | `registration_exclusion` 两轮通过，首次出现唯一预期 WARN_ON_ONCE | 串口 `mm/mmu_notifier.c:659 __mmu_notifier_register` 及 case 结果 |
| SMMU 范围归一化 | RANGE_INV 两种状态 × 8 范围向量，阈值等号及全 mm 正确 | `smmu_sva_size_normalization` 两轮通过 | SMMU suite 日志 |
| SMMU ops 结构 | legacy 与测试条件表分工，release/free 相同 | `smmu_sva_notifier_ops_shape` 两轮通过，仅结构证据 | SMMU suite 日志 |
| 模块生命周期 | 两套件加载、卸载后各再运行一次 | 4 次成功加载/卸载，PROTOTYPE_PASS、PROTOTYPE_EXIT=0 | 串口 PROTOTYPE_LOAD/UNLOAD/PASS/EXIT |
| 关闭 KUnit 与关闭 notifier | 有效关闭配置编译正确 | KUNIT=n 两个生产对象及 MMU_NOTIFIER=n 探针退出 0 | off/stub 配置与编译日志 |

每轮两个套件合计 13 个 KUnit 执行结果，两轮合计 26 个，通过率为本原型这些结果的 100%，不是分支覆盖率。注册循环和 size 循环中的向量不是独立 KTAP case，不额外计入 26。

允许告警精确限定为 `__mmu_notifier_register` 的本次非法组合校验一次；其余 WARN/OOPS/panic/失败/跳过均使脚本失败。外部测试模块未签名产生预期 OE taint 和签名提示，没有开启强制签名，没有篡改模块签名策略。基线 QEMU 缺少硬 watchdog 支持和 IMA 密钥文件的启动提示保留，不计为本特性通过证据。

## 运行过程中的环境与脚本问题

- cpu=max 在 QEMU 自身 `regime_is_user` 断言处退出，尚无内核输出，原始日志 `qemu-prototype-max.log`。同一 Image 改用 cortex-a72 后运行通过；未定位或修复 QEMU 内部根因，也不声称 max 平台通过。runner 可通过 QEMU_CPU 显式选择模型。
- 首次 cortex-a72 运行 notifier 已通过，但 parser 没有处理 CONFIG_PRINTK_CALLER 的相邻 `[T...]` 前缀。修正为剥离所有相邻前缀后，完整两轮通过；失败记录保留 `qemu-prototype-ktap-parser.log`。

## 测试有效性验证

在隔离快照中执行两个真实源码变异，测试源码未改动：

| 变异 | 实际结果 | 证据 |
|---|---|---|
| dispatcher 去掉 need_tlb 条件 | runner 退出 1；new_false、both_false 和 mixed counts 出现 1!=0、2!=1 等预期断言失败 | `qemu-prototype-mutant-dispatch.log` |
| 非 RANGE_INV 阈值比较从 >= 改为 > | runner 退出 1；size 归一化等号用例实际 2097152、期望 0 | `qemu-prototype-mutant-size.log` |
| 恢复原始源码并重建 | 源码 cmp/SHA256 与变异前完全一致，Image/modules 和外部模块构建退出 0，恢复后两轮再次全通过 | `mutation-summary.txt`、`mutation-restore-check.log`、`qemu-prototype-restored.log` |

共享源码未被变异；原 `qemu-prototype.log`、.config 和 Module.symvers 哈希保持不变。变异失败均到达目标断言，未将启动失败当作测试有效性证据。源码临时备份已清理，最终构建不含 mutant。最初保存的 good Image 备份在完成恢复后移除，历史哈希保留于摘要。
