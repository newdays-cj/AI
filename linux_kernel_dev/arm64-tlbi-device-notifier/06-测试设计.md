1. 在可睡眠准备阶段分配并 pin 存活 mm，创建独立订阅和预分配事件区；记录所有资源初始余额。
2. 按用例注册 old/new/neither，非法组合在专用启动运行；9 个向量各断言 -EINVAL。共享校验点 WARN_ON_ONCE 每次启动最多一次，不重置或要求逐向量新告警；白名单仅限 TC02.04.02 窗口、匹配构建的该注册校验点精确符号/源码位置，其他或重复 WARN 失败。

4. 保存调用者 IRQ/preempt 快照，再进入本向量要求的原子状态；不把测试 harness 的 pin 误算为实现自身 pin。
5. 调用获批 seam 指向的同一被测逻辑；保护区内只记录事件，退出后才做 KUnit 断言。
6. 对照下表检查完整序列、次数与参数；事件缺失、溢出、跨 CPU 读取均直接失败。正常路径在 .exit 释放缓冲前归档事件；fatal 路径只输出仍可安全取得的诊断，缺失证据不算通过。
7. 正常、核验不匹配与 fatal 退出统一由 `struct kunit_suite.exit = tlbi_test_fixture_exit` K14（`void (struct kunit *test)`）这个 per-case .exit 执行，不是 suite_exit，早于通用 resource cleanup：run_enabled=false、停止并等待 worker；所需 verified stub 仍在时销毁候选和假对象、清所有权并核对 ledger；K6 只 deactivate ledger 确认且 active 的目标并标 inactive，绝不停用核验失败目标；注销真实计数订阅者并等 SRCU/异步 free；释放 mm/缓冲/fixture 并清 test->priv。fake SVA 成功注册只在 ledger，不交真实 notifier_put。
