# 覆盖率：阶段⑥设计矩阵（selected split + G1–G4 blueprint）

**隔离软件原型证据优先说明**：主矩阵仍记录完整生产设计义务和未完成的验收。后续用户授权的原型已执行部分软件测试，第一阶段见 §8，实际回调运行的第二阶段见 §9，不将整个 ID 或分支自动置为通过。未采集 gcov，完整方案覆盖率仍 UNMEASURED。

## 1. 口径、状态与证据边界

- canonical 输入为完整当前 05§8：P1–P13=13、N1–N4=4、T1–T14=14、S1–S8=8、Z1/O1=2、K1–K47=47，合计 **88 ID**。ID 不等于 C 函数数，S2 含两表，typed leaf 同型替身同样纳入。
- 选定 A：conditional new=TLB-only、old=ATC-only；legacy old=combined。bit0 不表示 ATC 需求，不采用 B 的单消费者状态回调。
- 表中“设计”均为未来义务；G1–G4 蓝图已指定但未实现/审核通过。所有行实测 **U=UNMEASURED**，无测试、构建、QEMU、真机或 gcov 执行结论。
- 一次 SRCU/单遍逐项 need&&new 后 old；只保证同项 new 正常返回→old，不固定不同订阅者次序。SRCU 保护对象/ops 到配对结束，不阻止 release/unregister 并发开始。
- 每个 TC 引用均指 06 表内“场景”叶子，参数化向量必须逐项独立 fixture/KTAP，不能只报告一个总 PASS。源码/构建不折算 runtime 百分比。
- G1=持久候选 P11/P12/P13+K8/K9；G2=同 provider TU K5/K7 调实际 inline；G3=K10/K11 实际 S8+K12 实际 ATC 编码；G4=K1/K2 有界记录+显式 worker/cleanup。
- 禁止生产 static_key/base/caps/xarray/CMDQ mutation、复制算法、生产 generic ops。每 redirect 校验 in_task/current test 及 mm/dev/domain/smmu/candidate/resource 所有权；IRQ 中可见 current-test 不等于合法 fixture。
- E_RAW/E_KEY/E_BYPASS_RAW/G5/E_IO/E_ENTRY/E_CALLER/E_KUNIT_OOM 与 H1–H4/V/C 不从分母隐去。软件控制流可追踪不等于真实 I/O/指令或硬件完成已覆盖。

## 5. Seam K1–K47（含逐 API 同型替身）

以下表中 `test_原名` 均指 05§8.1 的完整同型替身名，不是一个泛型替身。T7–T13 已在上表逐项登记；K15–K40/K42–K44 的叶子 TC 各明确命名原函数及 test_ 函数，K41 没有替身。
每 API 的 fixture matched/mismatched/IRQ 上下文 guard 都是义务；T7–T9 负向 fallthrough 仅源码/构建，其他负向运行仅限 K2 no-op、bridge 提前拒绝等真正无破坏性路径。禁止假对象落入真实硬件/OF/资源调用；真实 forward 为 E_IO，不因 stub 安装计作执行。公开 kunit_activate_static_stub 返回 void，不证明成功。保留 kunit_hooks.get_static_stub_address 为 **TREE-PINNED INTERNAL** 依赖，不是公开 API：先检查 hook 非 NULL，每次 activation 返回后再次检查，并按精确 real fn lookup，必须等于预期 typed replacement 才记 verified active ledger；行为探针不能证明精确目标。每轮安装/重配 run_enabled=false，当前模式全部 verified 后才启用。hook 缺失/NULL/错误地址返回失败，runner（含 CHECK_ONLY）在真实入口/raw/OF/MMIO/CMDQ 前拒绝，缺失/停用记录同样拒绝；仅 deactivate ledger 确认且 active 项，绝不停用失败目标。
源码依赖：lib/kunit/static_stub.c:113-120 可 ctx 分配成功而 resource 分配静默失败；lib/kunit/test.c:444-450,476-484 的 per-case struct kunit_suite.exit（不是 suite_exit）早于通用 cleanup，cleanup kthread 设置 current->kunit_test=test 且 in_task，故清理 redirect guard 有效。禁跑只拦 runner，保留受保护析构 redirect。移植/升级前重新核验 hook 可见性/精确 lookup、activation 错误处理和 cleanup 次序/上下文，不能视为稳定公开 API。

## 7. 填充和退出规则

88 ID 是当前设计清单，不是 runtime 达标计数；逐行 TC→独立具名向量→KTAP/退出码→事件→源位置/gcov，未执行保持 U。
保留同一 `/home/chenjun/tools/qemu_arm64_defconfig` 基线及 out-of-source 构建；命令、脚本、gcov 采集均为 06§6–§7 未来计划，本轮未创建/执行。
只退出码0不够：预期suite/case及完整KTAP必须出现且ok；缺计划/缺终止/not ok/意外WARN/OOPS/lockdep/超时失败；SKIP有理由但仍未覆盖。
TC02.04.02 的 9 个非法注册向量各断言 -EINVAL；共享 WARN_ON_ONCE 每专用启动最多一次，白名单精确限定匹配构建/校验点符号与源码位置/执行窗口，不重置全局状态、不要求逐向量新 WARN；重复或其他 WARN 失败。K14 suite .exit 必须先于自动资源清理完成受保护析构；fixture 唯一由 .exit 释放，自动 activation cleanup 仅安全网。
安装验收必须逐次用 TREE-PINNED INTERNAL hook 核验精确目标，仅 verified 项入 ledger；void 返回不是成功。run_enabled 全核验前保持 false；核验失败在所有真实入口前返回失败，仅回收 ledger 确认项，绝不停用失败目标。E_KUNIT_OOM 保留已知框架私有 ctx 泄漏（不注入），不能用特性自有账平衡宣称全局平衡；移植前重验当前树 hook/activation/per-case .exit 与 cleanup kthread 源码依赖。
内联/常量折叠、源码/反汇编及配置stub证据单列，不换算硬件或runtime比例；保留所有例外并经技术审核，不删除分母凑100%。
后续新增生产helper、测试module init/exit、向量生成器/断言/脚本函数必须逐函数补两文档；这里不假装未来函数已全部列完。

历史文档计划批准不是本版技术签核，也不是生产内核实现许可；本轮仅传播05软件决策及测试蓝图，不宣称覆盖率达标。
