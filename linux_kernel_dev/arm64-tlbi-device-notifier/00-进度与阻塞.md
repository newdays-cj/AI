## 4. 历史方向与本轮选择

下文 A/B 为旧版比较。ATC 最新确认要求重新划分 TLB 与 ATC 回调职责，不能沿用“新槽独占整个合并回调”或“一律拒绝新旧槽并存”的提案。现有 `invalidate_range_start/end` 注册约束不是此次要擅自放宽的对象。CPU phandle 与 reg 配对等仍为软件 ABI 草案。

**方向 A**：功能激活时 nosync 就地同步完成；禁用 reclaim 合批；仅硬件确认 sticky aggregate 时保证每逻辑操作一次读取；issue/DSB/read 区间 pin CPU + 屏蔽 IRQ，读取后恢复再遍历回调；现有回调无条件一次，新回调 bit0==1 时调用。现有 page/range preDSB 时序可能需加强为 postDSB——未决兼容性边界，不假装保留精确时序。

**方向 B**：保留延迟，记录多组 (mm, range, issuing_CPU) 元数据，不假设单一 mm；须满足生命周期与原子内存约束。当前无证明可行，不排除未来解法。

## 10. ATC 补充前的设计里程碑（历史）

- 设计：独立 DT 节点中 `cpus[i]` 与 `reg[i]` 对应；`smmus` 列出允许切换的实例。这些属性及偏移 0/4 字节资源是软件 ABI 草案，compatible 使用元变量，不安装假厂商 binding。
- TLBI：active 时固定 CPU、屏蔽本地 IRQ、完成全部原始操作、最终 DSB 后只读一次，再恢复原状态并通知；覆盖 young/contpte，禁止 reclaim 延迟合批。
- SMMU（已被 ATC 确认修订）：不重复软件 TLB，但 ATC 独立于 bit0；整个合并回调不能直接接到条件槽。保留原 CMD_SYNC 等待、范围与 ATS 判断及既有错误策略，具体 API 分工待重审。
- 新发现：zcopy 和 OBMM 直接发用户 mm TLBI，方案补入 P9/P10 模块安全桥接及 Z1/O1 接入；不全局修改 raw TLBI 宏。
