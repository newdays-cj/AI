# 两组社区 HugeTLB HVO 补丁方案对照

本文比较两组邮件列表补丁的**目标、补丁组成和实现逻辑**。第一组以
Muchun Song 于 2026-09-10 发布的 v6（17 个补丁）为准；第二组以
James Houghton 于 2026-10-03 发布的 v2（20 个补丁）为准。这些是
对应版本的提案说明，不代表所有补丁都已进入主线。

## 1. Introduce section-based vmemmap optimization for HugeTLB

**目标：**把 HugeTLB 启动期专用的预先建立优化 vmemmap 映射流程，
转移到通用 sparse-vmemmap population 流程。HugeTLB 只需在对应的
`mem_section` 中记录 compound page order；通用流程依据 section 元数据
决定保留哪些 vmemmap backing、哪些尾部映射可复用共享页。这样可移除
为原专用路径保留的 `SPARSEMEM_VMEMMAP_PREINIT`，并为后续复用该机制
打基础。device DAX 的转换不在这 17 个补丁内。[v6 系列封面信][section-cover]

**补丁组成及主要目录：**

| 补丁 | 作用 | 主要代码位置 |
| --- | --- | --- |
| 1–2/17 | 调整 `mem_section` 布局约束和优化 order 命名，准备 section 元数据 | `include/linux/mmzone.h`、`mm/sparse.c`、`mm/sparse-vmemmap.c` |
| 3–4/17 | 常规初始化跳过共享尾部描述符；分配共享尾页时立即初始化其中的 `struct page` | `mm/mm_init.c`、`mm/sparse-vmemmap.c` |
| 5–8/17 | 按 section 的 compound order 计算 vmemmap 开销，并让通用建图流程分配或复用尾页 | `mm/sparse-vmemmap.c`、`mm/mm_init.c` |
| 9–10/17 | 提前初始化内存 section；HugeTLB 启动页写入 order 并切换到通用 population | `mm/sparse.c`、`mm/hugetlb.c` |
| 11–17/17 | 删除预初始化专用路径、过时的计算/标志，将 HugeTLB 私有状态收回模块内 | `mm/sparse*.c`、`mm/hugetlb*.c`、相关头文件 |

**执行顺序：**初始化 section 元数据 → HugeTLB 标记启动页的 compound
order → 普通 sparse-vmemmap population 读取 order 并建立共享尾页映射 →
初始化路径避免重复改写共享尾页；共享页在分配时已初始化。热插拔等
场景的 vmemmap 页数记账也要按优化后的实际页数计算。
[补丁 3/17][section-skip]、[4/17][section-tail]、
[5/17][section-account]、[8/17][section-map]、
[10/17][section-switch] 分别展示了这些环节。

这组补丁关注**启动期优化由谁建图、如何记录和复用 section 信息**；
它本身不是 arm64 运行中修改 PTE 的协议。封面信注明这是从
“Generalize HVO for HugeTLB and device DAX”拆出的 HugeTLB 子系列，
device DAX 及更广的整合留待后续。维护者在该系列讨论中回复称已将它
更新到 `mm-unstable`；这不等同于确认所有目标内核均已合入。
[v6 系列封面信及回复][section-cover]

## 2. Another attempt at HVO support on arm64

**目标：**解决 arm64 对正在使用的 vmemmap 页表进行 HVO 重映射时的
有效映射更新问题。启用 HVO 时，原 PMD block 拆为 PTE table，保留的
描述符仍映射真实 backing，其余尾部映射改指共享页并设为只读；恢复时
重新分配 backing，把共享映射改回可写。变更涉及物理输出地址和权限，
不能简单覆盖旧的有效页表项。[v2 系列封面信][arm-cover]

**补丁组成及主要目录：**

| 补丁 | 作用 | 主要代码位置 |
| --- | --- | --- |
| 1–10/20 | 修复 bulk restore 及失败后的部分优化状态，补足 TLB flush、通用 PTE 更新接口、架构启用条件与启动页描述符初始化 | `mm/hugetlb.c`、`mm/hugetlb_vmemmap.c`、通用接口 |
| 11–13/20 | 检测系统级 `bbm_through_af` 能力，实现 AF 辅助的有效 PTE 更新并使 arm64 接入 HVO | `arch/arm64/kernel/cpufeature.c`、`arch/arm64/include/asm/{pgtable,pgalloc,hugetlb}.h` |
| 14–15/20 | 加入 PTE 更新故障注入及 HVO 压力自测 | `mm/hugetlb_vmemmap.c`、`tools/testing/selftests/mm/` |
| 16–20/20 | 尝试把 AF 方法扩展到 PMD block→table 转换及测试；全部标为 **DO-NOT-MERGE** | arm64 页表代码、通用页表接口、自测 |

**AF 更新协议：**该提案依据 Arm 架构中“AF 未设置的 translation 不能
缓存在 TLB”这一规则，按以下顺序更新正在使用的 PTE：

1. 原子清除旧 PTE 的 Access Flag（AF）。
2. 使该地址之前的 TLB translation 失效。
3. 使用 `cmpxchg` 将 AF=0 的旧 PTE 替换为新 PTE；若检测到并发改动，
   则重试。

因此它仍然执行 TLB invalidation，而不是免除 TLB 刷新。清 AF 的
时间窗口要求系统 CPU 支持**硬件 AF 更新**，否则访问 vmemmap 可能
触发 fault。v2 将能力建模为系统特性，并约束 HVO 的启动期启用状态；
该有效 PTE 更新路径还排除 contiguous PTE。
[v2 系列封面信][arm-cover]、[补丁 12/20][arm-pte]

主路径仍依赖 **BBML3** 完成 PMD block 到 PTE table 的转换。试图
用 AF 方法也处理 PMD 转换、取消 BBML3 要求的补丁 16–20/20 被作者
明确标记为 **DO-NOT-MERGE**，其内存模型前提在封面信中也被指出尚
不完全确定。不能把这部分视为主路径已有的保证。封面信及补丁说明
证实了提案设计，不单独证明其后合入状态。
[v2 系列封面信及目录][arm-cover]、[补丁 13/20][arm-enable]

## 二者关系与本归档的边界

第一组调整**启动期 vmemmap 优化的元数据和建图时机**；第二组处理
**arm64 在运行中更新 vmemmap 映射的架构安全性**，方向互补。此目录的
`arm64-pre-hvo-v2/` 是 OLK-6.6 的本地适配补丁，既不是上述两组社区
补丁的原样回移，也不应把本地 QEMU 测试当作社区 AF 提案的硬件验证。
本地实现和验证边界见 `arm64-pre-hvo-v2/README.md` 与
`pre-hvo-validation/REPORT-v2.md`。
