# SMMUv3 EVTQ TRACE_EVENT 架构分析

## 1. 静态架构

### 1.1 模块组成

```
drivers/iommu/arm/arm-smmu-v3/
├── arm-smmu-v3.c          # 主驱动（非安全态）
├── arm-smmu-v3.h          # 主驱动头文件（寄存器、数据结构、宏）
├── arm-r-smmu-v3.c        # Realm 态驱动（CONFIG_HISI_CCADA_HOST）
├── arm-r-smmu-v3.h        # Realm 态驱动头文件
├── arm-s-smmu-v3.c        # Secure 态驱动（CONFIG_HISI_VIRTCCA_CODA）
├── arm-s-smmu-v3.h        # Secure 态驱动头文件
├── arm-smmu-v3-sva.c      # SVA 支持（CONFIG_ARM_SMMU_V3_SVA）
├── arm-smmu-v3-iommufd.c  # IOMMUFD 支持（CONFIG_ARM_SMMU_V3_IOMMUFD）
├── arm-smmu-v3-test.c     # KUnit 测试
├── Makefile                # obj-$(CONFIG_ARM_SMMU_V3) += arm_smmu_v3.o
└── trace.h                 # 【待新增】TRACE_EVENT 定义
```

### 1.2 关键数据结构

#### EVTQ 条目格式（硬件规范）

```c
// 每个 EVTQ 条目占 4 个 u64（32 字节）
#define EVTQ_ENT_SZ_SHIFT    5
#define EVTQ_ENT_DWORDS      ((1 << EVTQ_ENT_SZ_SHIFT) >> 3)  // = 4

// evt[0] 字段
#define EVTQ_0_ID            GENMASK_ULL(7, 0)    // 事件类型 ID
#define EVTQ_0_SSV           (1UL << 11)          // SubstreamID Valid
#define EVTQ_0_SSID          GENMASK_ULL(31, 12)  // SubstreamID
#define EVTQ_0_SID           GENMASK_ULL(63, 32)  // StreamID

// evt[1] 字段（标志位）
#define EVTQ_1_STAG          GENMASK_ULL(15, 0)   // Stag
#define EVTQ_1_STALL         (1UL << 31)          // Stall
#define EVTQ_1_PnU           (1UL << 33)          // Privileged/Unprivileged
#define EVTQ_1_InD           (1UL << 34)          // Instruction/Data
#define EVTQ_1_RnW           (1UL << 35)          // Read/Write
#define EVTQ_1_S2            (1UL << 39)          // Stage 2
#define EVTQ_1_CLASS         GENMASK_ULL(41, 40)  // Fault class
#define EVTQ_1_TT_READ       (1UL << 44)          // Translation table read

// evt[2] 字段
#define EVTQ_2_ADDR          GENMASK_ULL(63, 0)   // Fault address

// evt[3] 字段
#define EVTQ_3_IPA           GENMASK_ULL(51, 12)  // IPA (Stage 2)
```

#### 软件队列结构

```c
struct arm_smmu_evtq {
    struct arm_smmu_queue  q;       // 底层环形队列（base, llq, irq）
    struct iopf_queue      *iopf;   // I/O Page Fault 队列
    u32                    max_stalls;
};
```

#### 设备主结构

```c
struct arm_smmu_device {
    // ...
    struct arm_smmu_evtq   evtq;    // EVTQ 实例
    // ...
};
```

### 1.3 事件类型（当前已定义）

| 宏 | 值 | 含义 |
|----|-----|------|
| `EVT_ID_TRANSLATION_FAULT` | 0x10 | 翻译故障 |
| `EVT_ID_ADDR_SIZE_FAULT` | 0x11 | 地址大小故障 |
| `EVT_ID_ACCESS_FAULT` | 0x12 | 访问权限故障 |
| `EVT_ID_PERMISSION_FAULT` | 0x13 | 权限故障 |

> 注：SMMUv3 规范定义了更多事件类型（如 C_BAD_STE、F_STE_FETCH 等），但当前 OLK-6.6 仅定义了这 4 种，且需求明确不新增。

## 2. 动态行为

### 2.1 非安全态 EVTQ 处理流程

```
硬件中断
  │
  ▼
arm_smmu_evtq_thread()                    [arm-smmu-v3.c:2044]
  │
  ├─ queue_remove_raw(q, evt)             // 从 EVTQ 取 4×u64
  │    └─ 成功: evt[0..3] 已填充
  │    └─ 失败(-EAGAIN): 队列空, 退出内层 while
  │
  ├─ [★ TRACEPOINT 插入点]               // 跟踪所有事件，无过滤
  │
  ├─ arm_smmu_handle_evt(smmu, evt)       // 尝试处理 fault (仅 0x10-0x13)
  │    └─ ret=0: 已处理 → 跳过打印
  │    └─ ret!=0: 未处理 → 进入 ratelimit 检查
  │
  ├─ __ratelimit(&rs)                     // 限速
  │    └─ 通过: dev_info() 打印原始数据
  │    └─ 不通过: 跳过
  │
  └─ queue_sync_prod_in(q)                // 检查 EVTQ 溢出
```

**tracepoint 插入时机分析**:

| 插入位置 | 优点 | 缺点 |
|----------|------|------|
| 在 `arm_smmu_handle_evt()` **之前**（L2055 之后） | 跟踪**所有**事件（包括已处理的），完整视图 | 事件量可能较大 |
| 在 `dev_info()` 旁边（L2073 替换） | 仅跟踪未处理的事件 | 丢失已处理事件信息 |

**推荐**: 在 `arm_smmu_handle_evt()` 之前插入，以便获得所有事件的完整视图。tracepoint 本身开销极低（~100ns），不会显著影响性能。

### 2.2 Realm 态 EVTQ 处理流程

```
硬件中断
  │
  ▼
arm_r_smmu_revtq_thread()                [arm-r-smmu-v3.c:457]
  │
  ├─ rmi_smmu_read_event(ioaddr, evt)    // 从 Realm EVTQ 取 4×u64
  │    └─ 成功: evt[0..3] 已填充
  │    └─ 失败: break 退出外层循环
  │
  ├─ [★ TRACEPOINT 插入点]               // 跟踪所有事件
  │
  ├─ FIELD_GET(EVTQ_0_ID, evt[0])        // 提取事件 ID
  │
  ├─ __ratelimit(&rs)                     // 限速
  │    └─ 通过: dev_info() 打印原始数据
  │    └─ 不通过: 跳过
  │
  └─ 循环 (无溢出检查，Realm 由 RMM 管理)
```

### 2.3 并发语义

- `arm_smmu_evtq_thread()` 作为独立中断线程运行，不与 cmdq 竞争（EVTQ 和 CMDQ 是独立队列）
- `arm_r_smmu_revtq_thread()` 同样作为独立中断线程运行
- EVTQ 是 producer（硬件写入）/ consumer（驱动读出）模型，无自旋锁保护
- tracepoint 本身是 lockless 的（trace buffer 使用 per-CPU ring buffer）

## 3. 配置与构建

### 3.1 Kconfig 依赖

| 配置项 | 说明 | Trace 依赖 |
|--------|------|-----------|
| `CONFIG_ARM_SMMU_V3` | 主驱动编译开关 | 必需 |
| `CONFIG_HISI_CCADA_HOST` | Realm 态驱动编译开关 | 可选（覆盖 Realm 路径） |

`CONFIG_ARM_SMMU_V3` 本身已依赖 `CONFIG_TRACEPOINTS`（通过 IOMMU 框架间接依赖），无需额外 Kconfig 修改。

### 3.2 Makefile

```makefile
obj-$(CONFIG_ARM_SMMU_V3) += arm_smmu_v3.o
arm_smmu_v3-y := arm-smmu-v3.o
arm_smmu_v3-$(CONFIG_HISI_CCADA_HOST) += arm-r-smmu-v3.o
```

`trace.h` 作为 C 文件的 `#include`，**无需修改 Makefile**。

## 4. 外部接口

### 4.1 Trace 用户态接口

tracepoint 注册后自动暴露于：

| 接口 | 路径 |
|------|------|
| tracefs | `/sys/kernel/tracing/events/arm_smmu_v3/smmu_evtq_event/` |
| perf | `perf list \| grep arm_smmu_v3` |
| bpftrace | `bpftrace -e 'tracepoint:arm_smmu_v3:smmu_evtq_event { ... }'` |

### 4.2 内核态 Consumer

当前无其他内核模块消费 EVTQ 事件。tracepoint 仅为用户态消费设计。

## 5. 生命周期

- **初始化**: `arm_smmu_device_reset()` 中 `arm_smmu_init_one_queue()` 初始化 EVTQ，`request_threaded_irq()` 注册中断处理函数
- **运行时**: 硬件写入 EVTQ → 中断触发 → `arm_smmu_evtq_thread()` / `arm_r_smmu_revtq_thread()` 处理
- **卸载**: `arm_smmu_device_remove()` 中 `iopf_queue_free()` 释放 EVTQ 资源，`free_irq()` 注销中断

tracepoint 注册/注销由 `TRACE_EVENT` 宏自动处理，无需额外生命周期管理。

## 6. 差距分析

### 6.1 当前状态 vs 需求

| 维度 | 当前 | 需求 | 差距 |
|------|------|------|------|
| EVTQ 数据采集 | `dev_info()` 打印到 dmesg | TRACE_EVENT 按需采集 | 需新增 tracepoint |
| 事件过滤 | 仅 ratelimit 限速 | 支持 ftrace/perf 过滤 | TRACE_EVENT 天然支持 |
| Realm 态支持 | `dev_info()` 打印 | 同样支持 TRACE_EVENT | 需在 `arm-r-smmu-v3.c` 中插入 |
| 性能开销 | printk 路径较重 | tracepoint 透明开关 | tracepoint 关闭时 ~1ns |

### 6.2 参考先例

| 模块 | 文件 | 模式 |
|------|------|------|
| Intel IOMMU | `drivers/iommu/intel/trace.h` | TRACE_EVENT + `__string` + `__field` |
| HiSilicon IOMMU | `drivers/iommu/hisilicon/trace/trace.h` | `trace_ummu_event` — 用 `__dynamic_array` + `memcpy` + `__print_array` 记录原始数组 |

**推荐参考 HiSilicon 模式**：用 `__dynamic_array` + `__print_array` 直接记录 `evt[]` 数组，最简洁且完全匹配"仅原始数据"需求。

### 6.3 改动范围

| 文件 | 操作 | 改动量 |
|------|------|--------|
| `trace.h` | 新建 | ~30 行 |
| `arm-smmu-v3.c` | 新增 `#include "trace.h"` + 1 行 `trace_*` 调用 | 2 行 |

总计：2 个文件，~32 行变更。零 Makefile/Kconfig 改动。**不修改 `arm-r-smmu-v3.c`**。
