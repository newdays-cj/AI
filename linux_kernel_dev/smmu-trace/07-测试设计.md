# SMMUv3 EVTQ TRACE_EVENT 测试设计

## 1. 测试策略

| 类型 | 适用性 | 方法 |
|------|--------|------|
| 功能测试 | ✅ | QEMU 环境验证 tracepoint 注册、启用、数据采集 |
| 集成测试 | ✅ | 触发 SMMU 事件后验证 trace buffer 内容 |
| KUnit | ❌ | TRACE_EVENT 是基础设施，不适合单元测试 |

## 2. 测试前置条件

- QEMU ARM64 virt 环境（gic-version=3）
- 内核以 `~/tools/qemu_arm64_defconfig` 编译
- 确保 `CONFIG_ARM_SMMU_V3=y` 和 `CONFIG_TRACEPOINTS=y`
- 确保内核命令行包含 SMMUv3 初始化参数

## 3. 测试用例

### 用例 1：tracepoint 注册验证

**目的**：验证 TRACE_EVENT 正确注册到 tracefs。

**步骤**：
```sh
# 1. 检查事件目录是否存在
ls /sys/kernel/tracing/events/arm_smmu_v3/smmu_evtq_event/

# 2. 检查 enable/format 文件
cat /sys/kernel/tracing/events/arm_smmu_v3/smmu_evtq_event/enable
cat /sys/kernel/tracing/events/arm_smmu_v3/smmu_evtq_event/format
```

**预期结果**：
- 目录存在，包含 `enable`, `filter`, `format`, `id`, `trigger` 等文件
- `enable` 内容为 `0`（默认关闭）
- `format` 文件中包含 `evt0`, `evt1`, `evt2`, `evt3` 字段定义

### 用例 2：trace 启用与采集

**目的**：验证 tracepoint 可启用并采集数据。

**步骤**：
```sh
# 1. 启用 tracepoint
echo 1 > /sys/kernel/tracing/events/arm_smmu_v3/smmu_evtq_event/enable

# 2. 触发 SMMU 事件（例如访问无效 IOVA 的 PCIe 设备 DMA）
#    或者如果有已有故障设备，事件会自动产生

# 3. 读取 trace buffer
cat /sys/kernel/tracing/trace

# 4. 关闭 tracepoint
echo 0 > /sys/kernel/tracing/events/arm_smmu_v3/smmu_evtq_event/enable
```

**预期结果**：
- `cat /sys/kernel/tracing/trace` 中能看到 `arm_smmu_v3:smmu_evtq_event:` 行
- 每行包含 `evt:` + 4 个 16 进制 u64 值
- 格式如：`<devname> evt: 0x0000000000100000 0x0000000000000003 0x00000000fffc0000 0x0000000000000000`

### 用例 3：perf 工具采集

**目的**：验证通过 perf 可正常采集事件。

**步骤**：
```sh
# 1. 检查 perf 可见性
perf list | grep arm_smmu_v3

# 2. 采集 5 秒
perf record -e arm_smmu_v3:smmu_evtq_event -a -- sleep 5

# 3. 查看结果
perf script
```

**预期结果**：
- `perf list` 输出中包含 `arm_smmu_v3:smmu_evtq_event`
- `perf script` 能正确显示采集到的事件（如有事件触发）

### 用例 4：tracepoint 开销验证

**目的**：验证 tracepoint 关闭时无显著开销。

**步骤**：
```sh
# 1. 检查 tracepoint 默认关闭
cat /sys/kernel/tracing/events/arm_smmu_v3/smmu_evtq_event/enable
# 预期: 0

# 2. 检查 EVTQ 中断处理正常（无新增延迟）
#    通过 dmesg 观察，SMMU 初始化正常，无异常日志
```

**预期结果**：
- tracepoint 默认关闭，无性能影响
- dmesg 中无与 tracepoint 相关的异常

### 用例 5：现有行为不变

**目的**：验证 dev_info() 打印行为不变。

**步骤**：
```sh
# 1. 禁用 tracepoint
echo 0 > /sys/kernel/tracing/events/arm_smmu_v3/smmu_evtq_event/enable

# 2. 触发 SMMU 事件
# 3. 检查 dmesg
dmesg | grep "event 0x"
```

**预期结果**：
- `dev_info()` 打印格式不变：`event 0xNN received:` + `0xNNNNNNNNNNNNNNNN` 逐行输出
- trace 开关不影响 dmesg 行为

## 4. 测试执行计划

| 用例 | 优先级 | 依赖 | 预计时间 |
|------|--------|------|---------|
| 用例 1（tracepoint 注册） | P0 | 内核编译成功 | 1 min |
| 用例 2（trace 启用采集） | P0 | 用例1 + SMMU 设备存在 | 2 min |
| 用例 3（perf 采集） | P1 | 用例1 + perf 工具 | 2 min |
| 用例 4（开销验证） | P1 | 用例1 | 1 min |
| 用例 5（行为不变） | P1 | 用例1 + SMMU 事件可触发 | 2 min |
