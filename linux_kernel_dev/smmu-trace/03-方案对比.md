# SMMUv3 EVTQ TRACE_EVENT 方案对比

## 方案 A：固定字段（`__field` × 4）

**实现思路**：tracepoint 中将 `evt[0]` ~ `evt[3]` 分别展开为 4 个独立 `__field(u64, ...)`。

```c
TRACE_EVENT(smmu_evtq_event,
    TP_PROTO(struct arm_smmu_device *smmu, u64 *evt),
    TP_ARGS(smmu, evt),
    TP_STRUCT__entry(
        __string(iommu, dev_name(smmu->dev))
        __field(u64, evt0)
        __field(u64, evt1)
        __field(u64, evt2)
        __field(u64, evt3)
    ),
    TP_fast_assign(
        __assign_str(iommu, dev_name(smmu->dev));
        __entry->evt0 = evt[0];
        __entry->evt1 = evt[1];
        __entry->evt2 = evt[2];
        __entry->evt3 = evt[3];
    ),
    TP_printk("%s evt: 0x%016llx 0x%016llx 0x%016llx 0x%016llx",
        __get_str(iommu),
        __entry->evt0, __entry->evt1,
        __entry->evt2, __entry->evt3)
);
```

**调用方式**（仅 `arm_smmu_evtq_thread()`）：

```c
trace_smmu_evtq_event(smmu, evt);
```

## 方案 B：动态数组（`__dynamic_array` + `__print_array`）

**实现思路**：使用 `__dynamic_array` 存放整个 `evt[]` 数组，`TP_printk` 中用 `__print_array` 自动格式化。参考 HiSilicon IOMMU 的 `trace_ummu_event`。

```c
TRACE_EVENT(smmu_evtq_event,
    TP_PROTO(struct arm_smmu_device *smmu, u64 *evt),
    TP_ARGS(smmu, evt),
    TP_STRUCT__entry(
        __string(iommu, dev_name(smmu->dev))
        __dynamic_array(u64, evt, EVTQ_ENT_DWORDS)
    ),
    TP_fast_assign(
        __assign_str(iommu, dev_name(smmu->dev));
        memcpy(__get_dynamic_array(evt), evt,
               EVTQ_ENT_DWORDS * sizeof(u64));
    ),
    TP_printk("%s evt: %s", __get_str(iommu),
        __print_array(__get_dynamic_array(evt),
                      EVTQ_ENT_DWORDS, sizeof(u64)))
);
```

**调用方式**（仅 `arm_smmu_evtq_thread()`）：

```c
trace_smmu_evtq_event(smmu, evt);
```

## 对比

| 维度 | 方案 A（固定字段） | 方案 B（动态数组） |
|------|-------------------|-------------------|
| **性能** | 更优 — 字段 inline，零分配 | 略微差 — `memcpy` 到动态缓冲区 |
| **简洁性** | 逐字段书写，4 字段尚可接受 | 一行 `memcpy`，一行 `__print_array` |
| **可读性** | 输出逐字段并排 | `__print_array` 输出 `{ 0x..., 0x..., 0x..., 0x... }` 格式 |
| **扩展性** | 需修改 TP_STRUCT__entry 和 TP_fast_assign | 只需改 `EVTQ_ENT_DWORDS` 宏 |
| **内核先例** | Intel IOMMU `qi_submit` / `prq_report` | HiSilicon IOMMU `trace_ummu_event` |
| **上游接受度** | 更常见（内核主流模式） | 较少见（用于未知长度的数组） |
| **perf 字段可见性** | 每个 `evtN` 独立可过滤 | 整体作为数组，过滤不便 |

## 推荐

**推荐方案 A（固定字段）**，理由：

1. **EVTQ_ENT_DWORDS 是硬件常量（=4）**，未来不会变 — 无需动态数组的灵活性
2. **性能最优** — 字段直接嵌入 trace buffer，无额外 `memcpy`
3. **内核主流模式** — Intel IOMMU 的 `qi_submit`/`prq_report` 均使用 `__field` 逐项展开
4. **perf 友好** — 每个 `evt0..evt3` 可独立过滤（如 `perf record -e arm_smmu_v3:smmu_evtq_event --filter 'evt0 & 0xff == 0x10'`）
