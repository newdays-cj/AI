# SMMUv3 EVTQ TRACE_EVENT 需求描述

## 需求背景

SMMUv3 硬件通过中断上报 event 事件到 EVTQ（Event Queue），当前驱动仅在 `arm_smmu_evtq_thread()` 中通过 `dev_info()` 将未处理的事件原始数据打印到 dmesg。在生产环境中，大量事件会污染内核日志，且不具备线上事件的实时采集和过滤能力。

## 原始诉求

为 SMMUv3 EVTQ 事件添加 `TRACE_EVENT` 支持，使得用户可以通过 `/sys/kernel/tracing` 体系（tracefs、perf、bpftrace 等）按需采集、过滤和分析 SMMU 硬件事件，无需依赖 dmesg。

## 功能目标

1. 在 `arm_smmu_evtq_thread()` 中插入 `trace_*` 调用点，记录从 EVTQ 中取出的每条事件
2. 仅在 `arm_smmu_evtq_thread()` 中插入，不涉及 Realm 态路径
3. tracepoint 仅记录原始 EVTQ 数据（4 × u64），不做任何解码（保持最小开销）
4. 保留现有 `dev_info()` 打印行为不变，trace 为新增采集通道

## 约束条件

- **平台**: ARM64，SMMUv3 硬件
- **内核版本**: OLK-6.6（Linux 6.6.0 基础）
- **不修改**现有 `arm-smmu-v3.h` 中的 `EVT_ID_*` 宏定义（不新增事件类型）
- **不修改**现有事件处理逻辑
- **不修改**现有 `dev_info()` 打印
- **遵循**内核 TRACE_EVENT 编码规范

## 验收标准

1. 新增 `drivers/iommu/arm/arm-smmu-v3/trace.h`，包含正确的 TRACE_EVENT 定义
2. `arm_smmu_evtq_thread()` 中插入 `trace_*` 调用，**不修改 `arm-r-smmu-v3.c`**
3. tracepoint 可通过 `/sys/kernel/tracing/events/` 或 `perf list` 列出
4. 通过 `trace-cmd` 或 `perf record` 可采集到事件
5. 编译通过：`make -j$(nproc) Image` 零 error（arm64 目标）
6. `scripts/checkpatch.pl --strict` 零新增 warning/error
7. 不影响现有 EVTQ 中断处理和 `dev_info()` 打印行为
