# 架构分析

分析基线：kb/OLK-6.6/mm，gen_kernel_kb 已生成 overview（198个文件）。交叉阅读代码及 mmap.c 提交历史。

## 路径与缺口

- arch/arm64/kernel/sys.c 的 mmap flags 为 unsigned long，libc 接口通常为 int，应保持在低32位。
- mm/mmap.c __do_mmap_mm -> get_unmapped_area -> 文件/架构/THP/shmem 回调 -> __mmap_region_ext。MAP_SHARED 会过滤非 LEGACY_MAP_MASK 的位，编号须在过滤前转成 VMA 属性。
- vm_unmapped_area 是多数普通回调的最终搜索点；需要将预留区间视为不可用空洞，而非建立可被解除的占位 VMA。
- 固定地址、地址提示、文件自定义回调可绕过普通搜索；在顶层 get_unmapped_area 和实际插入路径双重校验。
- mmap_region、insert_vm_struct、copy_vma、vma_expand、do_brk_flags 和 expand_downwards 涉及直接地址空间建立/增长。mremap_to 在选址前已可能解除目标，须先验证范围，再允许破坏目标。
- 使用4个VMA高位存储0（普通）或1–8（编号），原有拆分、fork复制和合并比较继承规则，避免跨编号合并。mremap 转换回 mmap 标识维持编号。
- exec 临时栈、最终栈、ELF固定布局不允许侵入保留区；冲突可导致exec失败，不擅自重定位固定ELF地址。配置应避开预期程序、堆、栈、vdso布局。

## 生命周期与并发

注册仅启动期间，使用mutex串行化；规则和冻结状态 __ro_after_init，fs_initcall_sync 冻结，禁止晚注册。DTS为subsys_initcall，消费者最迟同步fs_initcall；rootfs_initcall才启用usermodehelper。运行态仅8项无锁只读遍历，原有 mmap_lock 保护进程VMA。compat按mm上下文判断。

## 配置与影响

独立ARM64 bool配置；DTS驱动单独bool、依赖OF，内建并在冻结之前扫描可用节点注册。built-in消费者必须在冻结前的initcall调用。不得覆盖配置。Kconfig与SHARE_POOL互斥，避免两个全局布局机制竞争。

验证重点：文件固定选址回调验证、大页对齐、编号跨边界增长、mremap提前解除目标、exec和compat、关闭配置。
