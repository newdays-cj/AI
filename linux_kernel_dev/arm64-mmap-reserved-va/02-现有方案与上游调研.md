## 对比

| 机制 | 来源 | 不足 |
|---|---|---|
| PROT_NONE 占位 + MAP_FIXED | https://man7.org/linux/man-pages/man2/mmap.2.html | 每进程应用维护，可被 munmap 或无编号 MAP_FIXED 替换，无全局编号注册。 |
| MAP_FIXED_NOREPLACE | 同上 | 检查现有 VMA 冲突，不预留未映射地址，无编号隔离。 |
| mseal | https://docs.kernel.org/userspace-api/mseal.html | 封存已有映射并阻止替换/解除，不提供可重复分配的编号范围。 |
| 社区 sealing 讨论 | https://lore.kernel.org/lkml/CAG48ez3ShUYey+ZAFsU2i1RpQn0a5eOs2hzQ426FkcgnfUGLvA@mail.gmail.com | mseal 官方文档所引用的讨论，主题为映射封存边界，不是全局地址范围注册方案；本次未独立获取邮件全文。 |
| OLK share_pool | include/linux/share_pool.h、mm/share_pool.c；git log -- mm/mmap.c | 专用共享池，固定布局，非八编号通用映射；存在选址限制，新增范围不能与其争用。 |
| vm_unmapped_area + get_unmapped_area | mm/mmap.c | 有有界 Maple Tree 搜索及文件专用回调，可复用，但没有持久预留规则、编号或增长隔离。 |

## 结论

按 Feature 推进。不将上述单一机制视为完整满足需求，也不触发早期终止。基线 mmap flags：bit21 已被 MAP_SHARE_POOL 使用，bit25 为 MAP_PEER_SHARED，bits26–31 为大页编码；ARM64 的 bit7 尚未定义，bits22–24 尚未定义，可采用 bit7 表示启用编号、bits22–24 表示0–7编号，避免扩展至 libc int flags 无法传递的高32位。该 ABI 为下游 ARM64 专用，不宣称上游标准。
