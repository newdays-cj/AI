# 实现方案

## 接口

- ARM64 UAPI：MAP_RESERVED_VA=0x80，MAP_RESERVED_VA_SHIFT=22，3位编号，MAP_RESERVED_VA_ID(n) 同时设置标识及编号，n为0–7。裸编号位但未带标识拒绝，关闭功能时请求拒绝。
- 内核：reserved_va_register(id,start,end)，启动期内建调用，不导出给模块；EINVAL非法、EEXIST重复/重叠、EPERM冻结后调用。无注销。区间需位于运行时支持的64位用户地址边界内。
- VMA高位52–55存储编号+1；普通为0。mremap继承；增长与插入入口按完整区间验证。
- DTS：compatible="openeuler,reserved-user-va"；子节点含 range-id、virtual-range（两个64位值：start、size）；扫描可用节点，以同一接口注册。不能使用reg混淆物理地址。

## 主要改动

include/linux/reserved_va.h、mm/reserved_va.c：表、注册/冻结、区间判定、编号与vmflags转换、普通选址避让、编号有界搜索及回调验证。
mm/mmap.c：公共搜索过滤、顶层选址/实际插入、brk、stack及直接VMA插入/移动/扩展校验。
mm/mremap.c：固定移动在解除目标前校验、选址继承编号、原地扩展带原编号。
arch/arm64 UAPI、include/linux/mm.h和mman.h：ABI、VMA属性及合法flags。
drivers/of/reserved_user_va.c：启动期DTS驱动；Kconfig、Makefile及binding、用户API文档。

## 关键契约

未配置编号ENODEV；范围耗尽ENOMEM；违反编号/固定边界EINVAL。原有文件权限、security_mmap_addr及文件/设备回调错误继续返回。普通地址提示落入预留范围时忽略提示重新选址。编号地址提示越界时忽略提示，仍只在指定范围搜索。MAP_FIXED_NOREPLACE原有EEXIST不变。

不伪造MAP_FIXED，不替换原回调。task_struct增加配置控制的unsigned long reserved_va_flags作为同步回调的任务局部选址上下文；reserved_va_get_area保存旧上下文、设置本次标识、调用原回调、恢复上下文；可睡眠/嵌套，不修改全局规则。sched_fork清零新任务字段。

vm_unmapped_area复制info，由reserved_va_prepare设置编号范围低高界，替代普通mmap_base布局策略，保留length、方向、align_mask/offset及Maple Tree的guard gap检查。普通搜索保持原始界限，由reserved_va_skip检查完整返回区间：bottom-up遇预留区将low提高至其end，top-down将high降至其start；重试至多越过8个区间，每次校验low<high和length<=high-low。编号上下文不执行普通排除，不会排除自身范围。

提示按完整区间检查，无效非固定hint改为0。回调仍返回越界时，非固定请求无hint重试一次，再越界返回EINVAL；固定请求直接拒绝。回调原错误保留，所有成功结果还须检查TASK_SIZE、页对齐及安全检查。->mmap后在合并/插入前复核完整范围与编号，不能改变编号。完全绕过公共搜索且不接受合法提示的特殊设备回调需适配该契约，不通过伪造固定映射绕过约束。

share_pool确定采用Kconfig depends on !SHARE_POOL，避免两个全局地址管理机制竞争；同时启用视为后续范围扩展。

内建模块与DTS先到先注册，不覆盖；注册失败明确日志。无需平台设备运行期probe、unbind或模块卸载。冻结后只读，运行态无新增锁。

## 函数契约、初始化与错误时序

- reserved_va_register(unsigned int id,unsigned long start,unsigned long end)：非__init且不导出；mutex串行，冻结优先检查，表和冻结标识__ro_after_init。独立KUnit模块仅调用测试配置下导出的桥接接口，不直接链接注册API。
- reserved_va_freeze(void)：fs_initcall_sync并使用同一mutex；DTS为subsys_initcall，消费者最迟同步fs_initcall，不支持异步延迟注册。init/noinitramfs.c及init/initramfs.c均在rootfs_initcall才usermodehelper_enable，因此常规用户执行前冻结。
- reserved_va_check(mm,start,len,vm_flags)：加法溢出拒绝；普通区间不得与8项交集；编号须存在并完整包含。compat按mm->context.flags判断，普通compat不限制但拒绝编号。空长度不引入新操作。
- reserved_va_vm_flags(flags)、reserved_va_map_flags(vm_flags)：普通0，编号为1–8往返转换；顶层拒绝无启用位的裸编号，关闭配置返回EOPNOTSUPP。
- reserved_va_get_area(get_area,file,addr,len,pgoff,flags)：同步作用域上下文、hint检查及一次无hint重试；reserved_va_prepare(info)、reserved_va_skip(info,addr)实现上述有界搜索，耗尽返回ENOMEM。
- mremap系统调用已在mmap写锁下vma_lookup并确认源存在，将有效VMA传入mremap_to；后者在两个do_munmap之前用源编号检查MREMAP_FIXED完整目标，范围规则拒绝不得破坏源/目标。保留原vma_to_resize重新查找以应对拆分；DONTUNMAP、自动移动及原地扩展均继承编号。不承诺其他已有错误无副作用。
- do_brk_flags、insert_vm_struct、copy_vma、vma_expand及expand_downwards修改前检查完整目标。__mmap_region先检查再解除旧映射，call_mmap后复核。remap_file_pages继承编号。
- DTS父节点可用才处理可用子节点；range-id精确4字节，virtual-range精确16字节；size非零且start+size无u64溢出。逐节点注册，失败日志含节点和errno，继续其余节点；已成功项保留，无隐式覆盖或回滚。

## 顺序与风险

先核心及入口覆盖、再DTS与文档、再测试。每个逻辑单元编译/checkpatch。未经用户明确要求不创建git提交，保留diff并可生成补丁。主要风险：ABI下游冲突、exec固定布局与配置冲突、自定义文件回调、内核内部VMA建立路径覆盖。实现后自审并按真实结果更新设计。
