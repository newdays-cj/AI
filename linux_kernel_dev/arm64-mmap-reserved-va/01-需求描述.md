# ARM64 mmap 编号选择预留用户虚拟地址范围

## 1. 状态与背景

- 阶段：① 已确认。用户接受 P01–P05 及 Feature 分级，并授权后续无重大问题自主推进，不再逐阶段请求确认；保留工作流规定的审核和验证。
- 基线：OLK-6.6，ARM64。
- 目标：为不同用途的用户态映射提供独立虚拟地址范围，通过 mmap flags 中的编号选择范围，并保证普通地址分配不能占用预留范围。
- 具体设备/业务背景尚未提供，不假定依赖特定设备。
- 本文区分用户已确认需求、建议规则和后续设计项；建议规则未经用户确认不作为已定要求。

## 2. 用户已确认需求

| 编号 | 要求 |
|---|---|
| R01 | 仅支持 ARM64 原生 64 位进程，不要求支持 32 位兼容进程。 |
| R02 | 共支持 8 个编号，由 mmap 的 flags 参数选择对应范围。编号的具体编码后续确定。 |
| R03 | 每个已注册编号对应一个连续的虚拟地址区间。 |
| R04 | 范围规则全局生效；各进程在自身虚拟地址空间中独立使用对应范围，不共享映射或物理内存。 |
| R05 | 严格隔离：只有携带对应编号的映射可以进入对应预留范围，普通映射和其他普通地址空间增长不能占用它。固定地址映射也不得绕过隔离。 |
| R06 | 指定编号后，仅能从对应范围分配，失败直接报错，不回退至普通范围或其他编号的范围。 |
| R07 | 提供内核注册接口，允许 built-in 模块注册各编号对应的范围。 |
| R08 | 提供内建驱动，通过 DTS 描述自定义范围并调用同一注册接口。 |
| R09 | 适用于匿名、普通文件、设备文件等所有类型的 mmap 映射；并不取消各映射类型原有的权限、对齐及其他合法性约束。 |
| R10 | 动态注册/注销生命周期难以控制，因此需求改为 built-in 使用方式；具体注册截止点仍待确认。 |

预留对象是用户虚拟地址范围，本需求不要求提前分配物理内存。

## 3. 补充规则（用户已全部确认）

| 编号 | 建议 |
|---|---|
| P01 | 所有注册均在启动阶段、首个用户态进程启动之前完成，此后冻结配置；不提供运行时注销接口。内建模块及 DTS 驱动须在截止点前完成注册，具体初始化顺序由设计明确。 |
| P02 | 同一编号只能成功注册一次，重复注册报错；DTS 与内建模块具有相同注册地位，均不能覆盖已成功注册的配置。不承诺 DTS 覆盖模块或模块覆盖 DTS。 |
| P03 | 各编号区间不得重叠；注册时校验编号合法性、有效用户地址边界、非空区间、页对齐和范围冲突。用半开区间 [start, end) 表达范围。 |
| P04 | 允许仅注册部分编号，选择未注册编号的 mmap 请求报错。 |
| P05 | 一次 mmap 仅选择一个编号；未指定编号明确表示普通映射，与全部 8 个编号相区别。 |

## 4. 功能约束与后续设计项

- 新特性须由独立 Kconfig 控制；关闭时保持原有行为。
- 用户 ABI 须能够区分普通 mmap 和 8 个编号，具体位域须核对 ARM64 现有 mmap flags 及调用链，不能直接假定某些位可用。
- mmap 地址提示、MAP_FIXED / MAP_FIXED_NOREPLACE 与编号的组合语义须明确：成功映射完整位于对应范围；普通固定映射不能进入任意预留范围。
- 隔离分析须覆盖 mmap、brk、栈增长、mremap、exec 布局，以及内核内部建立用户映射的路径，避免仅修改普通 mmap 搜索路径造成绕过。
- fork、exec、munmap 后全局范围规则继续有效；释放映射不意味着解除预留规则。移动、扩展映射如何保留范围约束由设计明确。
- 页大小、用户地址位宽、ASLR、文件自定义 get_unmapped_area、hugetlb 等约束须在调研与设计中验证；本需求不保证每类映射在任意区间配置下都能成功。
- 注册 API 签名、编号取值、errno、DTS compatible / 属性和 binding 文档、启动配置错误如何报告或处置，后续设计确定。
- 32 位兼容进程无需提供编号功能；不得因此破坏其原有普通映射行为。

## 5. 验收标准

以下为需求级验收目标；P 类对应的标准以用户接受建议为前提，详细用例和错误码在后续阶段细化。

| 编号 | 对应需求 | 可判定标准 |
|---|---|---|
| A01 | R02、R03、R06 | 为 8 个编号分别注册有效且满足测试映射要求的区间，在空间充足、请求合法时，每个编号至少一次映射成功；所有成功结果的完整区间均落在对应范围内，互不串用。 |
| A02 | R04 | 两个独立地址空间可在同一编号范围内分别建立映射，互不占用对方的可用空间。 |
| A03 | R05 | 无编号 mmap 的自动选址避开全部预留范围；普通固定映射落入或跨越预留范围时失败。 |
| A04 | R05 | brk、栈增长、mremap 及其他相关用户地址建立/调整路径不能绕过对应范围隔离；exec 布局不占用预留范围。测试方法在测试设计阶段明确。 |
| A05 | R06 | 耗尽对应范围后继续请求返回错误，即使普通地址空间或其他编号范围有空闲也不回退。指定编号的固定映射或地址提示不能导致范围外成功分配。 |
| A06 | R07 | 内建模块调用注册接口成功注册有效区间，后续用户映射遵守该区间。 |
| A07 | R08 | 使用自定义 DTS 启动后，驱动成功注册其中的有效配置，映射结果遵守 DTS 中的区间。 |
| A08 | R09 | 匿名、普通文件、设备文件三类映射在符合自身要求且区间有可用空间时可在指定范围建立；对特殊对齐映射验证原有约束仍成立。这些是代表性验收类别，不收缩 R09 的适用范围；特殊类型及完整覆盖清单由后续调研和测试设计补全。 |
| A09 | P02、P03 | 无效编号、空/非对齐/越界区间、重复编号、重叠区间注册失败，已有成功配置不被修改。 |
| A10 | P04、P05 | 部分注册时，未注册编号请求报错；普通无编号请求仍能在非预留范围正常映射，8 个编号均可独立表达。 |
| A11 | P01 | 截止点后注册失败且不改变已有配置；启动时内建模块、DTS 的有效注册均在冻结前完成。 |
| A12 | R01及功能约束 | ARM64 以规定 QEMU 基线配置构建并验证；关闭特性后普通映射行为保持原有语义，32 位兼容 ABI 不引入编号承诺或普通行为回归。 |
| A13 | R04、R05及生命周期约束 | fork 后父子进程继续遵守范围规则；munmap 释放的区间仍不能被普通映射占用；exec 后全局预留规则仍有效。 |
